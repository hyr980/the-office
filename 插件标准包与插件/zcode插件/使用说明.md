# 使用说明 —— 安装、配置、命令、故障排查

## 〇、前提（缺一不可）

- 办公室后端正在运行（默认 `http://127.0.0.1:8787`，端口以实际部署为准）；
- `node` 在 PATH 上（否则将配置项 `nodePath` 改为绝对路径）；
- ZCode 已登录可用；
- `zcodePath` 指向本机的 ZCode CLI 入口（**默认留空，须按你的机器配置**）。

## 一、安装

```
zcode plugins marketplace add "<本文件夹的绝对路径>"
zcode plugins install office-zcode@dev-office-zcode
```

- 安装后与更新后均需**完整重启 ZCode**（插件被复制进客户端缓存、按版本目录运行；
  `plugins update` 自身也会提示 "Restart zcode to apply"）。
- **更新流程**：先在源中提升版本号（`plugin.json` 与 `marketplace.json` 两处）→
  `zcode plugins update office-zcode@dev-office-zcode` → 重启客户端 →
  **终止旧常驻进程**（`~/.office-zcode/office-runtime.json` 中的 `pid`）。
  注意：常驻进程为 detached 进程，**不会**随客户端退出 —— 不终止它，hook 探测到它仍在响应，
  新版本将永远不会被拉起（0.1.1 → 0.2.0 升级时实测确认过此问题）。
- 注意：本市场清单的 id 与开发目录那个相同（`dev-office-zcode`）：若两侧都已注册，
  先执行 `zcode plugins marketplace remove dev-office-zcode` 移除旧市场，避免同名冲突。

## 二、配置 `~/.office-zcode/office-config.json`（不存在则新建；修改后需重启常驻进程）

| 键 | 默认 | 说明 |
| --- | --- | --- |
| `model` | 空 | 报到时上报的模型名（如 `GLM-5.3-Flash`）。**填写后照报，留空＝不报该项**（办公室卡上保留旧值）。本机已填 `GLM-5.3-Flash` |
| `iconFile` | 空 | 头像 PNG 路径。**留空＝自动取宿主安装目录自带的应用图标**（`resources\icon.png`，缺失时退至 `icon_windows.png`，再退至 PowerShell 抽取宿主 exe 图标） |
| `base` | `http://127.0.0.1:8787` | 办公室后端地址 |
| `memberId` | `zcode` | 在办公室中的身份（小写字母开头，长度不超过 32，报到时确定且不可变更） |
| `nick` | 空 | 昵称（AI 首次建卡时会收到一次提示，也可自行修改；传空串＝移除昵称） |
| `name` | `ZCode` | 宿主进程名（产品名写法，插件代报，AI 不可修改） |
| `port` | `19400` | 门牌号端口；被占用时先重试两次再退让（退让后需等待下一次报到） |
| `nodePath` | `node` | 启动常驻进程／投递使用的 node |
| `zcodePath` | （空） | ZCode CLI 入口；也可用环境变量 `ZCODE_CLI_PATH` |
| `mode` | 空 | 传给唤醒 CLI 的 `--mode`；空＝不传（CLI 对 `-p` 的默认值为 yolo） |
| `wakeGraceMs` | `15000` | 唤醒 CLI 的宽限毫秒（到时仍在运行＝视为「已被接受」） |
| `dataDir` | `~/.office-zcode` | 卡与运行时指针的落盘目录（**其中的接入手续卡不可删除**） |
| `verbose` | 关 | 开启后常驻进程日志写入 stderr |

凭据：本插件**不需要任何密钥**（办公室为本机 HTTP）。

## 三、五个斜杠命令

| 命令 | 层级 | 作用 |
| --- | --- | --- |
| `/office-connect` | 第一层 | 建立与办公室之间的常驻连接。**不涉及绑定** |
| `/office-disconnect` | 第一层 | 断开该连接。**不会自动重连**，恢复需再次执行 `/office-connect` |
| `/office-online` | 第二层 | 将**当前会话**绑定至办公室 ＋ 报到 ＋ 上线（需先连接）。命令在哪执行就绑定哪 |
| `/office-offline` | 第二层 | 仅撤销「在岗」，**不解除绑定**（地址保留，办公室仍可执行「叫它上线」） |
| `/office-status` | —— | 状态一览（连接状态／绑定的会话／当前会话／门牌号／**报到身份**：下次将提交的 model 与 icon 字符数） |

AI 也可直接调用这五个工具（`mcp__plugin_office-zcode_office__office_*`）与全部办公室原生工具
（`send_message`／`list_tasks`／`get_member` 等，同一前缀）。办公室推送 wake 叫醒时，
AI 在被叫醒的回合内即可自行执行 `office_online`。

## 四、常见故障排查

| 现象 | 排查方法 |
| --- | --- |
| 无法连接办公室 | 办公室后端是否在运行？`base` 是否正确？`/office-status` 查看「第一层连接」 |
| 上线失败「拿不到会话 id」 | hook 未上报过 —— 新装或更新后客户端是否已重启？`/office-status` 查看「当前会话」是否为空 |
| **叫醒无反应** | ① 未连接 ⇒ 办公室进入 silent，消息留存账本、待其上线后自行读取；② **headless 回合失败 ⇒ 见《验收到哪一步.md》：免费额度下服务端返回 `coding plan is required`，需 Coding Plan 档位（未验证项）**；③ 绑定的会话与预期不符 ⇒ `/office-status` 对照「绑定的会话／当前会话」 |
| 工具列表中没有 office 工具 | 客户端未完整重启（安装后与 update 后均需重启）；`zcode plugins list` 确认安装状态 |
| 门牌号漂移 | 19400 被其他进程占用 ⇒ 自动退让另选端口；需等待下一次报到办公室方能定位 |
| 成员卡 model/icon 不正确 | model：修改 `office-config.json` 的 `model` → 重启常驻进程 → 重新 `/office-online`（办公室「提交即覆盖」）；icon：0.2.0 起自动取宿主图标，重新报到即覆盖 |
| 报到被拒「空手」／接入被拒 | `~/.office-zcode/office-bridge-state.json` 被删除 —— 该文件为接入手续卡；更换成员 id 重新接入时才可删除 |
| 彻底重装 | `zcode plugins uninstall office-zcode@dev-office-zcode`；`~/.office-zcode` **不会**自动删除 |

## 五、自测（修改代码后执行）

```
cd plugins/office-zcode
node kernel/自测.mjs           # 内核部分（标准包原样）：22 条判据
node test/host-self-check.mjs  # 宿主部分：57 条判据（假办公室＋模拟 ZCode 安装树，不触及真实机器状态）
zcode plugins validate plugins/office-zcode
```

退出码 0 ＝ 全部通过。两套自测均不触碰真实办公室的任何数据。

# 实现说明 —— office-zcode 的实现

插件版本 0.2.0。「插件 ↔ 办公室」协议层为标准包内核**逐字节照搬**（未改一字，md5 可核）；「宿主 ↔ 插件」部分为本插件自行实现。全部代码零第三方依赖（仅使用 Node 内置模块与全局 `fetch`）。

## 一、文件一览（每个文件的职责）

| 文件 | 职责 |
| --- | --- |
| `..\marketplace.json` | 本地市场清单：市场 id `dev-office-zcode`，仅含插件 `office-zcode` 0.2.0，`source` 相对市场根指向 `plugins/office-zcode` |
| `.zcode-plugin\plugin.json` | 插件 manifest（ZCode 识别的第一优先级形态）：`name`／`version`／`description`／`author`，声明 `hooks`／`mcpServers`／`commands` 三类资源路径 |
| `.mcp.json` | 声明 stdio MCP 服务器「office」：`node ${CLAUDE_PLUGIN_ROOT}/host/office-mcp.mjs`。工具在 AI 侧的实际名称为 `mcp__plugin_office-zcode_office__<工具名>`（实测：ZCode 对插件提供的 MCP 服务器会在中间附加 `plugin_<插件id>_` 一段，与 Claude Code 的 `mcp__office__*` 命名规则不同） |
| `kernel\office-bridge.mjs` | 标准包内核，**逐字节照搬未改一字**（md5 `d98e5f39b0504f740adee900409539ba`，17433 字节）。维持 SSE 常驻连接、取卡存卡（`X-Office-Card`）、报到、转发工具调用、五个反向端点，均由它负责 |
| `kernel\自测.mjs` | 标准包的内核自测（原样保留，22 条判据，使用假办公室） |

| `host\office-config.mjs` | 配置解析（hook／常驻进程／MCP 三方共用）：内置默认值 → `~/.office-zcode/office-config.json` → 环境变量 `OFFICE_HOST_CONFIG`（供自测整体注入，存在时完全覆盖文件与默认值，保证自测不触及真实配置） |
| `host\office-runtime.mjs` | 运行时指针（`office-runtime.json`：`pid`／`ctlPort`／`hostPort`／`at`）读写；`pingCtl`；`ensureHost`（常驻进程不存在时以 detached 方式拉起并等待控制口应答） |
| `host\office-mcp.mjs` | MCP stdio 服务器（零依赖 JSON-RPC 2.0，每行一条消息）：五个控制工具与办公室原生工具的转发 |

## 二、关键流程所在的源码位置

（行号对应 0.2.0 源码；按函数名检索可得相同位置。）

1. **连接（第一层）**：执行 `/office-connect` → AI 调用 `office_connect` → 控制口 `/ctl/layer1`（`host\office-host.mjs` L369）
   → `bridge.connect()` → 内核 `connectOnce()`（`kernel\office-bridge.mjs` L179，发起 `GET /api/alive` 的 SSE 连接；
   若已绑定过会话则同时执行 `register(sid, true)`）。连接断开后**不会自动重连**（恢复需再次人工连接）。
2. **上线（第二层）＝绑定会话＋报到＋上线**：`/office-online` → `office_online` → `/ctl/link`（L390）
   → `bridge.online(sid)`（内核 `online()`）：先绑定 `boundSessionId`，再 `register(sid, true)`，再向办公室报告 `presence: online`。
   会话 id：请求体携带则用请求体的，否则使用 hook 上报的「当前会话」。
3. **报到**：内核 `register()`（L143）—— **每次报到都会重新读取** `opts.name/nick/model/icon`（宿主修改槽位即生效，无需重建内核）
   与门牌号。宿主侧代报：`name`（配置项，产品名写法，AI 不可修改）与 `host`（反向端点，AI 无法得知）；
   **model＝配置项照报**（`office-config.json` 的 `model`，留空则不报该项）；
   **icon＝三级来源**（`office-host.mjs` `resolveIcon` L120：显式 `iconFile` → 自动查找宿主自带应用图标
   `findAutoIconPng` L77 —— 由 `zcodePath` 反推安装目录取 `resources\icon.png`，缺失时退至 `icon_windows.png`，
   自动选取的文件做 PNG 魔数校验 → 以 PowerShell 抽取宿主 exe 关联图标 `grabHostIconByPs` L91）。
   办公室回传四格卡（id/joined/name/icon），内核落盘至 `~/.office-zcode/office-bridge-state.json`，
   此后每次建立连接均携带 `X-Office-Card`（`cardHeader()` L131）—— 此即「接入手续」，缺失将被办公室拒绝。
4. **叫醒（办公室 → 插件）**：办公室 POST `http://<门牌号>/dsh-office/wake`（内核 L240）→ `hookWake(why)`
   → 宿主 `wakeText()`（L215）套用「进来看看」模板 —— **下推的仅为命令、不携带正文**（正文在办公室账本中，AI 进入后自行读取）
   → `enqueueDeliver()`（L151，串行队列，避免同一会话被连续推送时相互覆盖）→ `deliverOnce()`（L157）
   → `runCliWithGrace()`（L182）启动 `node <zcode.cjs> -p "<进来看看>" --resume <绑定的会话id> --json`。
   宽限期（默认 15 秒）内以非 0 退出＝如实报告失败（附 stderr 尾部）；宽限期内未退出或退出码 0＝视为已送达。
   实际现状：免费额度下该回合被服务端拒绝（`coding plan is required`）—— 详见《验收到哪一步.md》。
5. **插话**：`/dsh-office/interrupt`（内核 L247）→ `steer` → **经同一条 CLI 路径排队投递**
   （ZCode 不具备「插入正在运行的回合」的接口，此为降级实现，README 已如实注明「这不是插话」）。
6. **工具转发（AI → 办公室）**：AI 调用 `mcp__plugin_office-zcode_office__<工具>` → MCP `callOffice()`
   （`host\office-mcp.mjs` L157）→ 控制口 `/ctl/call`（L408）→ `bridge.callTool()` → `POST <办公室>/api/call`。
   两处特判：`register` 由插件代填 host／name／memberId／sessionId（AI 无法得知，也不允许代他人填报）；
   `presence: online` 转为走 `/ctl/link`（会话 id 取控制口记录的「当前会话」）。
7. **状态查询**：`office_status` → `/ctl/state`（L351）→ 内核状态 ＋ 向办公室查询自身 presence（4 秒缓存）
   ＋ `report`（下次报到将提交的 model／icon 字符数 —— 使报到身份可见）。

## 三、实测确认的实现要点

- **工具实际名称**：`mcp__plugin_office-zcode_office__*`，而非 `mcp__office__*` —— 唤醒文案与五个命令文件均按实际名称书写。
- **斜杠命令的展开属于 TUI 侧行为**：`zcode -p "/office-connect"` 不会展开，字面量直接进入对话；在 headless 中执行相同动作需将命令正文作为提示发送。
- **hook 的 stdout 必须为空**：ZCode 按严格 schema 解析 hook 输出，多余字段即判错 ⇒ `session-start.mjs` 日志全部走 stderr、无论成败退出码均为 0。
- **内核持有 `opts` 的引用**：`createOfficeBridge(bridgeOpts)` 之后宿主随时修改 `bridgeOpts.model/icon` 即等于修改下次报到提交的内容（内核每次报到重新读取）—— 0.2.0 的自动头像依赖此特性，无需重建内核。
- **单实例**：相同数据目录仅允许一个常驻进程（指针新鲜度 ＋ pid 探活，后启动者自行退出）；门牌号端口固定 19400，被占用时先重试两次再退让（退让后门牌号变更一次，需等待下一次报到办公室方能定位）。

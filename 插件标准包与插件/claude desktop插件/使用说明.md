# 使用说明 —— office-desktop（Claude Desktop 的代码选项卡接入办公室）

插件版本 0.1.0。这份讲**怎么把它用起来**：装、配、按哪两个按钮、出问题看哪里。
原理与实现分别见《原理说明.md》《实现说明.md》；验到哪一步见《验收到哪一步.md》。

---

## 一、装

**本机这一版没有 `claude` 命令行**（PATH 里查不到），所以官方那两条命令
（`claude plugin marketplace add …` ＋ `claude plugin install …`）在本机用不了。两条可行路径：

### 1. 正式装（走应用界面）

1. 打开 Claude Desktop 的**代码选项卡**；
2. 点输入框附近的 `+` → **Plugins** → **Add plugin**；
3. marketplace 填本包根目录：

   ```
   <本包根目录：`claude desktop插件\` 的绝对路径>
   ```

   市场清单是本包根目录下的 `.claude-plugin\marketplace.json`（市场 id `dev-office-desktop`，
   只含一个插件 `office-desktop`，其本体在 `plugins\office-desktop\`）；
4. 装完**什么都不用启动**：随便开一个新会话，输入框上方那一条带自己就在了。

### 2. 开发时热加载

把 `plugins\office-desktop\` 整个目录拷进宿主盯着的那个「插件开发目录」，由宿主在本次会话里加载。
改一次模块文件即重载一次，窗口一关就没了。
（宿主第一次发现该目录时会问一句「是否为本会话启用热重载」，**要人点一下「启用」**。）

### 3. 不装、又要每次自动加载（点名目录）

本机没有 `claude` 命令行，若也不想走界面，就用**配置里点名**这条：在**配置目录**的 `settings.json` 里加一段 ——

```json
{
  "env": {
    "CLAUDE_CODE_PLUGIN_DIRS": "<本包 plugins/office-desktop 的绝对路径，用正斜杠>"
  }
}
```

（就在**配置目录**下的 `settings.json`；引擎也认进程环境里的同名变量。）

- **要点**：这个变量是**进程启动时读的** ⇒ 写完必须**重启应用**才生效；生效后插件「在进程启动时就在」，
  因此会走到**第一次 `session.start`** —— 也正因为如此，**只有这条与界面正式装能让那些工具进给模型的清单**
  （热重载属于「后来的那一次」，只跑钩子、不进清单；见《验收到哪一步.md》）。
- **代价**：它是**全局**设置，这台机器上所有会话都会加载这个目录；不想用了把这个键去掉或删掉该文件即可。

### 4. 装完之后怎么确认装上了

- 看**输入框正上方那一条**：应出现以「办公室」开头的一行（见《原理说明.md》§四）；
- 没有的话，看**调试日志**里有没有 `hooks module … loaded` 这一行；
- 会话里打 `/office`，会列出当前接入状态（连着没／绑的是哪个会话／门牌号／卡在哪）。

## 二、配置

配置项都在 `plugins\office-desktop\.claude-plugin\plugin.json` 的 `userConfig` 里声明，**每项都有默认值**。
改法与宿主一致（配置菜单或 settings 的 `pluginConfigs`，以插件名 `office-desktop` 为键）。

| 键 | 默认值 | 什么时候要改 |
| --- | --- | --- |
| `officeUrl` | `http://127.0.0.1:8787` | 办公室不在本机默认端口时 |
| `memberId` | `claude-desktop` | 换一个身份接入时（**格式 `^[a-z][a-z0-9_-]{0,31}$`**，报到时定终身，改了就是新成员） |
| `nick` | 空 | 想直接定昵称时（留空也行，首次建卡时内核会问 AI 一次） |
| `name` | `Claude Desktop` | 一般不动。它是**卡上的宿主进程名**，由插件代报 |
| `model` | 空 | 想固定报某个模型名时；留空 ＝ 自动取本会话当前的模型 |
| `port` | `19391` | 与别的接入端抢端口时。**门牌号端口固定住才不会跨重启变化** |
| `dataDir` | `~/.claude/office-desktop` | 一般不动。**里面那张卡别删**（见 §五） |
| `nodePath` | `node` | PATH 里找不到 node 时，填绝对路径 |
| `iconFile` | 空 | 想让办公室的成员卡上有头像时，填一张 PNG 的路径 |
| `verbose` | 关 | 排查问题时打开（常驻进程的日志进调试日志） |

## 三、按哪两个按钮（这一步是接入的全部操作）

**两个按钮，不合并**，都在**输入框正上方那一条**上：

| 按钮 | 管哪一层 | 按下去的后果 |
| --- | --- | --- |
| **连接 ／ 断开** | 第一层：办公室 ↔ 插件 | 连上／断开这台机器与办公室之间的那条线。**不碰绑定**（绑的是哪个会话不受影响） |
| **上线 ／ 下线** | 第二层：插件 ↔ 本 AI | 上线 ＝ **绑住当前这个会话** ＋ 报到 ＋ 上线；下线 ＝ **只撤「在岗」，不解除绑定**（地址留着，办公室里点「叫它上线」才叫得到人） |

**顺序**：先「连接」，再「上线」。没连上就点「上线」，那一条会写明「还没连上办公室：得先点『连接』」。

**鼠标**直接点；**键盘**在输入框空着时按 `1` ＝ 连接／断开、按 `2` ＝ 上线／下线（按钮上就画着这两个热键）。

**几条不许**（设计使然）：起来不自动连；断了不自己重挂 —— 恢复都要人重新点「连接」；
「上线」绑的是**人点它的那一刻所在的会话**，插件不替人挑会话。

**那条带上的三档字**要点：

| 显示 | 含义 |
| --- | --- |
| `尚未绑定` | 还没人点过「上线」 |
| `目前页面为绑定会话` | 叫醒会叫到这一页 |
| **`目前页面不是绑定会话`**（醒目色） | 绑的是**别的**会话 —— 叫醒会叫到那边去。要改就点「下线」再点「上线」 |

## 四、AI 侧怎么用（工具在哪、名字是什么）

上线之后，办公室的工具会逐个注册到会话里，AI 直接就能调。名字的规矩是本宿主定的：

```
办公室工具：  mcp__office-desktop__<办公室那边的原名>     例：mcp__office-desktop__send_message
插件自带自检： mcp__office-desktop__desk_status
```

（这条规矩各宿主不同 —— 同为办公室接入插件，ZCode 那边实测是 `mcp__plugin_office-zcode_office__*`。
本插件的前缀 **`mcp__office-desktop__` 已实测**：加载后注册着 28 个该前缀的工具，逐条名单见《验收到哪一步.md》。）

**表由 AI 自己进办公室填**：接任务、发消息、交付、表态都是 AI 调这些工具完成的，插件不代填；
插件只代报两个 AI 填不出的值 —— **门牌号**与**宿主进程名**。

**自检工具 `mcp__office-desktop__desk_status`** 也会被注册（它不是办公室工具，不经内核转发），
它报：那一行画过几次、画在哪个面、`$.tool.list()` 里注册着的工具真名、两层状态、绑定会话、门牌号、卡在不在。

**`/office` 命令**（会话里打）是给人看的：接入状态一览。它只是辅助，两个按钮不在这里。

## 五、常见故障排查

| 症状 | 先看什么 | 多半是什么 |
| --- | --- | --- |
| 输入框上方那一条没出现 | 调试日志里有没有 `hooks module … loaded` | 插件没加载（或那一行的树没通过校验，日志里会写原因） |
| 那一行在，点「连接」不动 | `/office` 的输出；办公室地址对不对；办公室后端在不在跑 | 办公室没开，或地址填错。界面上会写「连不上办公室（它没开？）」 |
| 点「上线」报「上线失败」 | `/office` 里「办公室说」那一行 | 办公室拒了；常见原因是**接入手续（那张卡）对不上** |
| 连上了、也上线了，但叫不醒 | `/office` 里「绑定的会话」是不是当前这一页；办公室日志里有没有 `推给插件（/dsh-office/wake）：HTTP 200` | 绑定指向别的会话（那一档在带上是醒目色）；或门牌号变了还没重报（点一次「上线」） |
| **办公室后端重启过（或中途断过）** | `/office` 里「第一层」是不是「未连接」 | 那条常驻连接也会跟着断，而插件**不会自己连回来**（设计如此）⇒ **要人重新点一次「连接」**；点完若显示未上线，再点一次「上线」（重启后的办公室要重新拿到报到与会话映射） |
| 办公室回 `接入手续没对上…`、工具整批被拒 | `dataDir` 里还有没有 `office-bridge-state.json`；里面有没有 `card` | 那张卡丢了或对不上。**卡是接入手续**：丢了要清掉该成员在办公室那边的卡，重新走一遍首次接入 |
| 改完代码行为没变 | 那一回合是否结束；紧凑着调一次本插件注册的工具（引擎会先重载再跑） | 热重载是「这一回合结束时」发生的；改模块文件也会让那条线断一次（要人重新点「连接」） |

**一条硬规矩**：`dataDir` 里那份状态**不要删**。它装着接入手续那张卡与「上一次绑过的会话」。

## 六、收摊

- **断开**：点「断开」（只断第一层，不动绑定）；**下线**：点「下线」（只撤在岗，不动绑定）。
- **不再使用**：在 Plugins 面板里停用或移除该插件。
- **办公室侧**：办公室记着这位成员的卡与门牌号；要彻底注销，得在办公室那边把这成员清掉。

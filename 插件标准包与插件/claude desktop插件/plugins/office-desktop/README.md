# office-desktop —— 把 Claude Desktop 的代码选项卡接进「办公室」

> 依据：《插件标准包与插件》的《说明书》＋ 内核 `office-bridge.mjs`（照搬，未改一字）。
> 定位：**站在「办公室」和 Claude Desktop 代码选项卡里的一个会话之间** —— 替那个 AI 挂住那条线、
> 收办公室推来的叫醒、把它叫起来、往它会话里插话，并把路通到办公室门口（**表由 AI 自己进去填**，插件不代填；
> **两个按钮画在输入框上方那一条带上**，由人点）。
>
> 写这套东西时的宿主版本、node 版本、内核校验值等，见 §八「版本与运行环境」；
> 验到哪一步见 §十。

**术语速查**（这几个词正文里反复用，第一次出现的地方也各解释了一句）：

| 词 | 什么意思 |
| --- | --- |
| **办公室** | 一套多 agent 协作台：一个人（系统内身份 `boss`）与若干 AI 在里面派发、执行、交付（《说明书》§0） |
| **接入插件** | 要接进办公室的那一层，站在「办公室」与「某个 AI 的会话」之间（《说明书》§0） |
| **两半** | 这件事被劈成两段：**「插件 ↔ 办公室」**（协议，标准包定死）＋ **「宿主 ↔ 插件」**（各家自定）。本插件两半都在这儿 |
| **宿主** | 跑这个 AI 的那个程序。这份文档里指 **Claude Desktop 的代码选项卡**（引擎是 Claude Code，与命令行同一个引擎、共享配置） |
| **门牌号** | 办公室**反过来找到插件**的地址（`主机:端口`）。本插件的门牌号 ＝ 那个常驻进程监听的 `127.0.0.1:<端口>`（《说明书》§2 第四步） |
| **常驻进程** | 本插件的 `host/office-host.mjs`：一个活到会话结束的 node 进程，内核跑在里面（§二 有「为什么」） |
| **连接／上线** | 两层，各管各的。**连接** ＝ 办公室与插件之间那条线；**上线** ＝ 插件把这个 AI 绑到某个会话上（《说明书》§1 第 7 件） |
| **AbovePrompt** | 本宿主插件 API 里「**输入框正上方那一条**」的官方名字 —— 两个按钮就画在那儿 |

## 一、先看这个：代价、前提、边界

**要付的代价**（都是设计使然，不是缺陷）：

| 代价 | 出处／为什么 |
| --- | --- |
| **要一个人点按钮**，AI 自己上不了线 | 《说明书》§1 第 7 件：两个按钮**由人在会话页面上控制**；§8 第 6／7 条：**不自动连、断了不自己重挂** |
| **多一个常驻进程**（一个 node 进程 ＋ 两个监听端口） | 那条常驻连接是 SSE、五个反向端点要有人监听端口，钩子模块两样都做不了（§二） |
| **改模块文件会让它掉线一次** | 插件目录被盯着，存文件即重载 ＝ 老进程被收掉、新的默认不连（恢复靠人按「连接」） |
| **`dataDir` 里那份状态不能删** | 里面有**接入手续卡**：对已建过卡的 id，办公室要求接入时必须带上它，空手会被当场回绝 |
| **插件只在本机会话可用** | 官方写明：插件（mod）在命令行与桌面应用的代码选项卡里工作；**云会话、WSL 会话不适用**。本插件按这一条写 |

**前提**：

- 办公室后端要在跑（默认 `http://127.0.0.1:8787`，《说明书》§3）。
- 那个 AI 的宿主得有「能把一段话投进某会话」的口 —— 这一段《插件怎么写》§0 明说**各家不同、标准包不规定**；
  本宿主的做法见 §六 ③。
- 本机要有 `node`（常驻进程用它跑）。

**边界（哪天会不成立）**：

- 只在**本机这一版引擎（Claude Code 2.1.288，跑在 Claude Desktop 代码选项卡里）**上写过、验过。换版本要重新看，
  尤其是**插件 API**（声明文件每次加载重铺，事件与 `$` 上的东西可能变）。
- 本机是 Windows；路径写法（`~`、反斜杠）按 Windows 写。
- **两个按钮「真的画出来了」这一条，本机未验**（未验的完整清单与原因见 §十）。

## 二、它是什么：两半

标准包 README 把这件事劈成两段，本插件的两半正好各管一段：

| 段 | 谁规定 | 本插件里是谁 |
| --- | --- | --- |
| **插件 ↔ 办公室** | **标准包规定**（一套 HTTP，只有这一套） | **`kernel/office-bridge.mjs`** —— 标准包那份内核，**逐字节照搬，一个字没改** |
| **宿主 ↔ 插件** | **各家不同，标准包不规定**（《插件怎么写》§0） | **`host/office-host.mjs`** ＋ **`hooks/register.tsx`** |

```
office-desktop/
├─ .claude-plugin/
│   └─ plugin.json              # 清单：插件名（office-desktop）、配置项（userConfig）、状态契约
├─ hooks/
│   ├─ hooks.json               # 指明唯一的钩子模块
│   └─ register.tsx             # 插件这半：那条带 ＋ 两个按钮 ＋ 唤醒/插话 ＋ 递工具 ＋ 自检工具
├─ host/office-host.mjs         # 常驻进程：把内核跑起来 ＋ 一条只认本机的控制口
├─ kernel/office-bridge.mjs     # 标准包的内核（照搬；字节数与 md5 见 §八）
├─ types/index.d.ts             # `$.state` 的类型契约（那条带的读数）
├─ test/host-self-check.mjs     # 自测：拿**假**办公室把常驻进程整个驱动一遍（47 条判据）
├─ test/wake-drill.mjs          # 演习：拿**真**办公室 ＋ 本接入端的真门牌号走一遍叫醒（18 条判据）
└─ README.md                    # 本文件
```

（目录里另会多出 `.claude-plugin\types\` 与一个 `tsconfig.json`：那是**引擎每次加载这个插件时自己铺下的**，
不属本插件的内容 —— 换台机器、重新加载都会重铺一遍。）

**为什么非得有那个常驻进程**（不是多此一举）：钩子模块跑在一个**没有 DOM、没有 Node** 的环境里
（官方声明文件原话：「A hooks module runs in an environment of its own: no DOM, no Node」），而接进办公室要的两样东西它都给不了：

- 那条常驻连接是 **SSE**（一直读、永不结束，《说明书》§2 第一步），而宿主给的取网口是「读完整个 body 才回」，
  握不住一条不结束的流；
- 五个反向端点（办公室 → 插件，《说明书》§2 第四步）**要有人监听一个端口**，钩子模块里没有服务器。

⇒ 于是分成两半：**内核 ＋ 协议**跑在常驻进程里，**界面 ＋ 唤醒会话**跑在钩子模块里。两半之间两条线：

- 内核 → 插件：常驻进程往 **stdout 写一行 JSON**（`{"t":"wake",…}` 等）；
- 插件 → 内核：插件往那条**只监听 127.0.0.1 的控制口**打 POST（`/ctl/state`、`/ctl/link`…）。

## 三、装法

**本机这一版没有 `claude` 命令行**（PATH 里查不到），所以官方那两条命令
（`claude plugin marketplace add …` ＋ `claude plugin install …`）在本机**用不了**。可用的两条路：

**① 走应用界面装（正式，首选）**

1. 打开 Claude Desktop 的代码选项卡，点 `+` → **Plugins** → **Add plugin**；
2.  marketplace 指向本包根目录 `claude desktop插件\`（市场清单在 `.claude-plugin\marketplace.json`，
   插件本体在其 `plugins\office-desktop\`）；
3. 装完新开一个窗口，那条状态带自己就在了。

**② 开发时热加载（改一下就重载一次，窗口一关就没了）**

把 `plugins\office-desktop\` 整个目录拷到一个「插件开发目录」，由宿主在本次会话里盯着它：
存文件即重载钩子模块。本机自测时用的就是这条路（目录见《验收到哪一步.md》）。

**但这条路有一个天生的短处（本机实测）**：热重载晚于「进程启动」⇒ 引擎只把**进程启动时就在的插件**
那一次 `session.start` 里注册的工具列进给模型的清单；热重载属于「后来的那一次」，只跑钩子
⇒ 工具**注册成功但不进清单**。⇒ 要让 AI 真调得动办公室的工具，走 ① 或 ③。

**③ 不装、又要每次自动加载（点名目录）**

在**配置目录**的 `settings.json` 里点名这个插件目录（配置目录在哪，见 Claude Desktop 自己的说明）：

```json
{
  "env": {
    "CLAUDE_CODE_PLUGIN_DIRS": "<本包 plugins/office-desktop 的绝对路径，用正斜杠>"
  }
}
```

- **进程启动时读** ⇒ 写完要**重启应用**；生效后插件「在启动时就在」，会走到第一次 `session.start`，
  那些工具因此进清单（与 ① 等效）。
- 它是**全局**设置：这台机器上所有会话都会加载这个目录；不想用了去掉这个键即可。

- **卸载**：在同一个 Plugins 面板里移除即可。
- **验「装没装上」**：新窗口里那一行（输入框上方那条带）在不在；不在就看 §九 的排查。
- **改模块文件 ＝ 掉线一次**：`hooks/register.tsx`、`hooks/hooks.json`、`.claude-plugin/plugin.json` 这些
  引擎要读的文件，存一下即重载；重载会把常驻进程收掉（那条 SSE 跟着断），而**新的默认不连** ⇒ 恢复只能由人按「连接」。

## 四、人怎么用它：**输入框上方那一条**（两个按钮）

《说明书》§1 第 7 件要的那个位置，在本宿主里就是**输入框正上方的那条带**（官方名字 `AbovePrompt`）。
本宿主引擎的声明原文：**「Raised on the terminal and desktop surfaces only」** —— 终端面与**桌面面**都升起。

那一行画出来的样子（文字按从左到右的顺序）：

```
办公室  已连接  已上线（本页面）  目前页面为绑定会话  3f2a91c7  127.0.0.1:19391  1: 断开   2: 上线
```

| 按钮 | 管哪一层 | 点了算什么 |
| --- | --- | --- |
| **连接 ／ 断开** | **第一层**（办公室 ↔ 插件） | 连上／断开**这台机器跟办公室那条线**。**不碰绑定**，哪个会话页面都能点 |
| **上线 ／ 下线** | **第二层**（插件 ↔ 本 AI） | 上线 ＝ **绑住当前这个会话** ＋ 报到 ＋ 上线；下线 ＝ **只撤掉「在岗」，不解除绑定**（地址留着，办公室才叫得到人 —— 内核 `office-bridge.mjs` 的 `offline()` 注释写的就是这一条） |

**怎么按**：

- **鼠标**：直接点那两个按钮。
- **键盘**：两个按钮都带热键，画成 `1: 连接`、`2: 上线` 这样。**输入框空着**时按 `1` ＝ 连接／断开，按 `2` ＝ 上线／下线
  （引擎的规矩：空输入框里一个「光秃秃的数字」会交给那一条上的按钮）。
- 副作用：输入框空着时打头按 `1`／`2`，会被当成按键而不是正文。

**三档绑定关系必须看得见**（《说明书》§8 第 10 条）—— 绑定指向别的会话时，表面一切正常，人不会知道「叫醒会叫到别处去」，
所以那一档**用醒目的颜色标出来**：

| 显示 | 什么意思 |
| --- | --- |
| `尚未绑定` | 还没人点过「上线」 |
| `目前页面为绑定会话` | 就是这一页 —— 叫醒会叫到这里 |
| **`目前页面不是绑定会话`**（醒目） | 绑的是**别的**会话 —— 叫醒会叫到那边去 |

**起来不自动连、断了不自己重挂**（《说明书》§1 第 1 件、§8 第 6／7 条）。两条都要人点。

会话里另有一个 **`/office`** 命令，打出来是当前接入状态的一览（连着没／绑的是哪个会话／门牌号／卡在哪／那一行画过几次）。
它只是**辅助**，两个按钮不在这里 —— 按钮在那条带上。

## 五、配置（`plugin.json` 的 `userConfig`；改这里或写进 settings 的 `pluginConfigs`）

每一项都有默认值，一个不填也能跑。

| 键 | 默认值 | 说明 |
| --- | --- | --- |
| `officeUrl` | `http://127.0.0.1:8787` | 办公室后端地址（默认值出处：《说明书》§3） |
| `memberId` | `claude-desktop` | 本接入端在办公室里是谁。格式 `^[a-z][a-z0-9_-]{0,31}$`（《说明书》§2 第二步），**报到时定终身**。与 Claude Code 那个插件（`claude`）各算一位成员 |
| `nick` | 空 | 昵称。留空也行 —— 首次建卡时内核会问 AI 一次，AI 自己也能改 |
| `name` | `Claude Desktop` | **宿主进程名**（《说明书》§2：产品名写法，不是可执行文件名）。由插件代报，AI 改不了 |
| `model` | 空 | 报的模型名。**留空 ＝ 自动取本会话当前的模型**（`$.session.model()`；每次点「上线」还会刷新一次） |
| `port` | `19391` | 门牌号端口。**固定住门牌号才不跨重启变化**；被占时**先占两次原端口再退让**，实在占不上才退回随便挑一个（会写一行日志）。默认与 Claude Code 那个插件的 `19390` 错开 |
| `dataDir` | `~/.claude/office-desktop` | 卡与「上一次绑过的会话」落盘处。**里面有那张接入手续卡，别删**（§一、§九） |
| `nodePath` | `node` | 起常驻进程用哪个 node；PATH 里找不到时填绝对路径 |
| `iconFile` | 空 | 头像 PNG 的路径。首次报到把它的 base64 交给办公室；留空 ＝ 不报头像 |
| `verbose` | 关 | 打开后常驻进程的日志进调试日志 |

## 六、《说明书》七件事，各自落在哪一行

| # | 要做什么（《说明书》§1） | 本插件怎么做的 |
| --- | --- | --- |
| 1 | 维持一条常驻连接 | 内核挂 `GET /api/alive`（SSE，内核 `connectOnce()`）；**断了不自己重挂**（同处注释写的就是这一条） |
| 2 | 能收 | 内核收办公室推来的一切；`wake`／`interrupt` 由常驻进程递到插件这半（stdout 一行 JSON） |
| 3 | 能唤醒 | 收到 `wake` ⇒ `$.prompt.submit({ text })` 往**绑定的那个会话**投一句「进来看」。**推的只有命令，不带正文**（§5 硬要求 2） |
| 4 | 能插话 | 收到 `interrupt` ⇒ `$.session.append` 把那句**原样**插进会话（用户角色的一行，模型当轮读到）；**插完即止，不等回话**（§1 第 4 件） |
| 5 | 让 AI 够得着工具 | 拉 `GET /api/tools` ⇒ `$.tool.register` 逐个注册；**填表发生在办公室侧**（§1 第 5 件） |
| 6 | 报到 | 内核报 id／会话／模型；**门牌号与宿主进程名由插件代报**（AI 填不出这两个值 —— §2 第二步）；头像走 `iconFile` |
| 7 | 两个按钮 | `hooks/register.tsx` 里 `ui.render` 的 **`AbovePrompt`**（＝输入框上方那一条，§四） |

五个反向端点（`/dsh-office/wake`／`interrupt`／`online`／`connect`／`challenge`）全在内核里
（`office-bridge.mjs` 的 `buildServer()`），一个不多一个不少（《说明书》§2 第四步：仅此五个）。

**工具在这个宿主里的名字。**

本宿主的钩子 API 声明原文：`ToolSpec.name` ——「The tool's short name (letters, digits, `_`, `-`; up to 64);
**the model calls it as `mcp__<plugin>__<name>`**」。

⇒ 本插件的插件名是 `office-desktop`（`.claude-plugin/plugin.json` 的 `name`），因此：

| 哪一类 | 真名 | 举例 |
| --- | --- | --- |
| **办公室工具**（由 `GET /api/tools` 递上来，逐个注册） | `mcp__office-desktop__<办公室那边的原名>` | `mcp__office-desktop__send_message`、`mcp__office-desktop__read_messages`、`mcp__office-desktop__presence` |
| **本插件自带那个自检工具** | `mcp__office-desktop__desk_status` | 报「那一行画过几次／画在哪个面／工具在本宿主的真名／两层状态与绑定会话」 |

**这条规矩各宿主不一样，别照别家推**：同为「办公室接入插件」，ZCode 那边实测到的名字是
`mcp__plugin_office-zcode_office__send_message`（它在中间垫了一段）。本插件用的不是 MCP 服务器形态，
而是本宿主的 `$.tool.register`，声明写死了是 `mcp__<插件名>__<工具名>` 这一段。
**本机已实测**（2026-10-07）：插件加载后自报的 `$.tool.list()` 里注册着 **28 个** `mcp__office-desktop__*`
（27 个办公室工具 ＋ 自带的自检工具 `desk_status`），逐条名单与凭据见交付包《验收到哪一步.md》。
⇒ 本文件顶部那处 `TOOL_PREFIX` **实测正确，不用改**；日后换宿主若发现前缀变了，要改的也只有这一处。

## 七、几条要说在明面上的

**① 内核是照搬的，改没改可以自己核**

```
字节数 17433 ／ md5 d98e5f39b0504f740adee900409539ba
```

（本插件 `kernel/office-bridge.mjs` 与标准包 `office-bridge.mjs` 是同一个 md5；§八 有复核命令。）

**② 门牌号来自内核自己起的端口**（`127.0.0.1:19391`），不是「从宿主请求头里学来的那个」。
内核的做法是它自己起一个 http 服务（内核 `start()`），注释写明的理由：
「不借宿主的 webServer —— 那样换宿主就用不了」。⇒ 本插件**以内核为准**。

**③ 「宿主 ↔ 插件」这一段是各家自己的**（《插件怎么写》§0），本插件的两处落地是这么选的：

| 办公室要的结果 | DSH 那个现成插件的做法（《插件怎么写》§1） | 本插件（Claude Desktop）的做法 |
| --- | --- | --- |
| 叫醒：**AI 当轮看得见**「进来看」 | `sessionController.prompt({ mode:'queue' })` | `$.prompt.submit({ text })` —— 同样是**排队**：会话忙着先排着，等它手上这轮干完再开一轮 |
| 插话：**插进会话**、不等回话 | `sessionController.prompt({ mode:'steer' })` | `$.session.append({ message:{ type:'user', content:[…] } })` —— 那一行**当场进会话**（存成 `isMeta` 的用户行，模型读得到、人不当自己打的看）；**它不开新的一轮**，所以是「插完即止」 |

**④ 叫醒「送到了没有」是真的去问的，不是蒙的**：常驻进程把 `wake` 递给插件后会**等回话**（10 秒），
拿到 `ok` 才回给办公室；送不到时**抛错**（不是返回 false），好让内核答成 `{ok:false, error:"上线异常…"}` ——
那是《说明书》§5 要求办公室拿到的形状，界面据此显示「上线异常」。
一处边界：插件那一头只等 **1.5 秒**就回话（过了就当「已投进队列」）——
`$.prompt.submit` 是「等那一轮真开起来才 resolve」的，若会话正忙，这里分不出「排上了」和「还没排上」。

**⑤ 那张卡别删**。`dataDir` 里的 `office-bridge-state.json` 存着**接入手续卡**：
对**已经建过卡的 id**，办公室要求接入时必须带上它，**空手会被当场回绝**（申请时实测撞到过：不带卡时办公室回
`接入手续没对上…`，工具调用整批被拒）。

**⑥ 头像是可选的**。标准包那份 DSH 插件是抽宿主 exe 的图标；本插件用 `iconFile` 指一张 PNG。
留空就是没头像，不影响接入。

**⑦ 门牌号变了要等下一次报到**。办公室推叫醒用的是**卡上记的门牌号**；端口变了（`port` 被占而退让）之后，
办公室要等**下一次报到**才更新那个位置 —— 而报到发生在点「上线」时，或连接建立时（已绑过会话才会顺手重报）。
⇒ 一般情况下（端口固定）不会遇到；遇到了，点一次「上线」即可。

**⑧ 自检工具是插件自己加的**，不是办公室工具（不经内核转发）：调 `mcp__office-desktop__desk_status`，
它会报那一行画过几次、画在哪个面、`$.tool.list()` 里的工具真名、两层状态、绑定会话、门牌号、卡在不在。
故障排查先看它。

**⑨ 出问题时先看 `/office`**：它把当前状态一行一行列出来（宿主进程在不在、连着没、绑的是哪个会话、门牌号、卡在哪）。
若那一行根本没出现，按 §九 的三条查。

## 九、自测

```bash
node test/host-self-check.mjs     # 拿假办公室：宿主侧那半 47 条判据
node test/wake-drill.mjs          # 拿真办公室＋本插件真门牌号：叫醒那一路 18 条判据
```

- 第一支**起一个假办公室**（不碰真办公室的任何数据），把常驻进程整个驱动一遍：连没连、绑没绑、
  推 wake／interrupt／online／connect／challenge 会怎样、断了会不会自己爬回来、卡落没落盘。退出码 0 ＝ 全过。
- 第二支反过来，连**真办公室**：把本插件自己的接入端起起来，扮演"人点了连接与上线"，再由另一个成员发一条消息，
  看办公室是不是真的往门牌号推了 `wake`、内核是不是真的把它递到了插件那一半。退出码 0 ＝ 全过。
  （它会在办公室里留下 `drill-*` 临时成员卡，可自行清理；卡存在系统临时目录下，**别删** —— 那是接入手续。）

内核本身的自测在标准包里（那份验的是「插件 ↔ 办公室」这一段）。

**出问题时按这三条查**：

1. **那一行没出现** ⇒ 插件没加载（或那一行的树没通过校验）。看调试日志里有没有
   `hooks module … loaded` 这一行。
2. **那一行在、但点了「连接」不动** ⇒ 看 `/office` 的输出：宿主进程在不在跑？办公室那个地址对不对？
3. **连上了但叫不醒** ⇒ 办公室推叫醒要求**对方连着**且**卡上的门牌号是对的**（§七 ⑦）；再看 `/office` 里
   「绑定的会话」是不是当前这一页（《说明书》§8 第 10 条那一档）。

### 写这个文件时的三条硬规矩（改代码前先看）

本宿主引擎加载钩子模块时**照源文扫描**，写法上卡三处：

1. **`$` 一律在调用处写成 `$.noun.method(...)`**。要把 `$` 交给本文件自己的辅助函数时，
   那个函数**必须声明在文件最外层**（函数声明，或 const 绑到一个函数）—— **嵌在别的函数里的闭包不算**。
   ⇒ 本文件里那些 `function xxx($, ...)` 全在最外层，别把它们挪回 `register()` 里。
2. **`on` 一律写成 `on("<事件>", 钩子)`** —— **不许拿 `on` 当形参或变量名**（会遮蔽引擎的全局 `on`）。
   ⇒ 「连接」那个布尔参数因此叫 `want`，不叫 `on`。
3. **`next` 不许当变量名**（那是钩子的第三个参数）⇒ 「下一份读数」那个局部变量叫 `nextStatus`。

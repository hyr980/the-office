# 实现说明 —— office-desktop 是怎么实现的

插件版本 0.1.0。「插件 ↔ 办公室」协议层为标准包内核**逐字节照搬**（未改一字，md5 可核）；
「宿主 ↔ 插件」部分为本插件自行实现。全部代码零第三方依赖（只用 Node 内置模块与全局 `fetch`）。

## 一、文件一览（每个文件的职责）

| 文件 | 职责 |
| --- | --- |
| `..\marketplace.json` | 插件市场清单（**根目录副本，与应用真正读的那份一字不差**） |
| `..\.claude-plugin\marketplace.json` | **应用真正读的那份**：市场 id `dev-office-desktop`，只含插件 `office-desktop`，`source` 指向 `./plugins/office-desktop` |
| `.claude-plugin\plugin.json` | 插件 manifest：`name`（`office-desktop`）、`version`、`description`、`types`（状态契约）、`userConfig`（十个配置项，各带默认值） |
| `hooks\hooks.json` | 指明唯一的钩子模块：`{ "modules": ["./register.tsx"] }` |
| `hooks\register.tsx` | **插件这半**（「宿主 ↔ 插件」那一段）：那条带 ＋ 两个按钮、叫醒与插话、把办公室工具递到 AI 面前、自检工具、`/office` 命令 |
| `host\office-host.mjs` | **常驻进程**：把内核跑起来；开一条只监听 `127.0.0.1` 的控制口；在 stdout 与插件那半说话 |
| `kernel\office-bridge.mjs` | 标准包内核，**逐字节照搬未改一字**（md5 `d98e5f39b0504f740adee900409539ba`，17433 字节）。挂 SSE、取卡存卡（`X-Office-Card`）、报到、转发工具、五个反向端点，全归它 |
| `types\index.d.ts` | `$.state` 的类型契约：`PluginState['office-desktop']` 下三个值（`status`／`note`／`working`） |
| `test\host-self-check.mjs` | 宿主侧自测：**假办公室**，47 条判据，不碰真办公室 |
| `test\wake-drill.mjs` | 叫醒演习：**真办公室** ＋ 本接入端的真门牌号，18 条判据 |
| `README.md` | 插件自带说明（装法／用法／代价／边界／七件事落点／版本／验证状态的完整版） |

## 二、两半之间的两条线

```
内核（常驻进程内）  ──stdout 一行 JSON──▶  插件模块
   {"t":"ready", ctlPort, hostPort, hasCard, …}
   {"t":"wake", id, why}          ← 叫醒
   {"t":"interrupt", id, text}    ← 插话
   {"t":"fatal", error}

插件模块  ──POST（只打 127.0.0.1）──▶  常驻进程的控制口
   /ctl/state   取读数（那条带每 2 秒拉一次）
   /ctl/layer1  人点「连接／断开」
   /ctl/link    人点「上线」（绑会话 ＋ 报到 ＋ 上线）
   /ctl/unlink  人点「下线」（只撤在岗，不解绑定）
   /ctl/call    AI 调一个办公室工具（转发）
   /ctl/reply   插件回话：那两件事（叫醒／插话）办成了没有
```

**为什么必须回话**：办公室要的是 `{ok}`。不等就答 `{ok:true}`，等于把「送到了没有」蒙一个 ——
尤其「叫它上线」那一条，办公室要靠 `{ok:false, error:"上线异常…"}` 在界面上显示「上线异常」。

**为什么配置走环境变量**（`OFFICE_HOST_CONFIG`，一个 JSON）：插件那半的目录被热重载盯着，
往里头写文件会被当成「改了插件」而触发重载（自己把自己重启）。头像只给**路径**，由常驻进程自己去读。

## 三、关键流程所在的源码位置

（行号对应 0.1.0 源码；按函数名检索可得相同位置。）

1. **起常驻进程** —— `hooks\register.tsx` 的 `startHost()`（L181）。只在 `session.start`（交互式会话）或**人点按钮**时起，
   **绝不自动连办公室**；读它的 stdout 的那个循环故意不被等（要跟会话一样长命）；进程退出后**不自动重启**。
2. **连接（第一层）** —— 人点「连接」⇒ `doLayer1()`（L407）⇒ 控制口 `/ctl/layer1`（`host\office-host.mjs` L226）
   ⇒ `bridge.connect()` ⇒ 内核 `connectOnce()`（`kernel\office-bridge.mjs` L179，发起 `GET /api/alive` 的 SSE）。
   点断开会掐掉那条流，且**不会自己连回来**（内核同处注释写的就是这一条）。
   内核在**已绑过会话**时会顺手重报一次（`register(sid, true)`，把门牌号一起报上去）。
3. **上线（第二层）＝ 绑定会话 ＋ 报到 ＋ 上线** —— 人点「上线」⇒ `doLayer2()`（L432）⇒ `/ctl/link`（L246）
   ⇒ 内核 `online(sid)`（L307）：先写 `boundSessionId`、再 `register(sid, true)`、再报 `presence: online`。
   会话 id 取的是**当前这一页的会话 id**（`$.session.id()`）—— 绑哪个会话由人点它时所在的那一页决定。
4. **报到** —— 内核 `register()`（L143）。**门牌号与宿主进程名由插件代报**（AI 拿不到这两个值）：
   宿主进程名来自配置项 `name`（默认 `Claude Desktop`，产品名写法），门牌号来自内核实际监听的 `127.0.0.1:<端口>`。
   办公室**回传那张卡**（四格 `id/joined/name/icon`）⇒ 内核落盘到 `dataDir\office-bridge-state.json`
   ⇒ 此后每次挂连接都带上（`X-Office-Card`），**此即接入手续**。
5. **叫醒** —— 内核的 `wake` 钩子（`host\office-host.mjs` 的 `bridgeOpts.wake`）⇒ 往 stdout 写一行
   ⇒ 插件 `handleLine()`（L265）⇒ `wakeText()`（L319）拼那句「进来看」⇒ `submitWithGrace()`（L341）
   ⇒ `$.prompt.submit({ text })`（排队）⇒ 回话给控制口 ⇒ 内核据此答办公室 `{ok}`。
   送不到时**抛错**（不是返回 false），好让办公室拿到带原因的 `{ok:false}`。
6. **插话** —— 内核的 `steer` 钩子 ⇒ `{"t":"interrupt", text}` ⇒ 插件 `$.session.append()` 把那句**原样**插进会话。
7. **递工具** —— `syncTools()`（L470）拉 `GET /api/tools`，逐个 `$.tool.register()`
   （注册出来的名字见 README §六）；办公室可能还没起来 ⇒ `armToolSync()`（L500）每 5 秒再试，最多 120 次。
8. **转发一次工具调用** —— `tool.call` 钩子（L657）：本插件自带那个自检工具就地答；
   其余转发到 `/ctl/call`。两处特判：`presence`（AI 自己上线／下线走内核对应用户会话的路径）、
   `register`（代报门牌号与宿主进程名）。
9. **那一行（两个按钮）** —— `ui.render` 钩子、`{ component: 'AbovePrompt' }`（L735）。
   画之前先读会话状态；**渲染钩子里不写状态**（本宿主不允许），所以「那一行画过几次」这类运行态记在模块变量里，
   由自检工具报出来。

## 四、与蓝本（Claude Code 那版）的关系：抄了什么、新写了什么、改了什么

蓝本是给 **Claude Code（命令行）** 做好的同款成品。本插件按**本宿主**的实际情况重写，逐条如下。

**照抄蓝本的（架构与思路）**

| 项 | 说明 |
| --- | --- |
| 两半的分法 | 内核跑在常驻进程里、界面与会话动作跑在钩子模块里 —— 理由相同（SSE 与反向端点） |
| 常驻进程的全部机制 | stdout 一行 JSON 的协议、六个控制口路由、只监听 `127.0.0.1`、配置走环境变量、退出不自动重启 |
| 内核与协议 | 内核逐字节照搬；五个反向端点一个不多一个不少 |
| 两个按钮的两层分工 | 连接／断开不碰绑定；上线绑当前会话、下线只撤在岗 |
| 那一条带上要显示的三档绑定关系 | 含「不是绑定会话」那一档用醒目色 |
| 叫醒／插话的落地方式 | `$.prompt.submit` 叫醒（排队）、`$.session.append` 插话；只推命令不推正文 |
| 三条写法硬规矩 | 辅助函数必须在文件最外层；`on`／`next` 不许当变量名 |
| 工具转发的三种结局 | 办成回字符串、办公室拒了回「拒绝」那一档、接入端没在跑时说清楚 |
| 自测的形态 | 一支假办公室驱动常驻进程、一支连真办公室走叫醒 |

**新写的（蓝本里没有）**

| 项 | 为什么加 |
| --- | --- |
| 自检工具 `mcp__office-desktop__desk_status` | 本机没有命令行（跑不了 `claude plugin validate` 之类），需要一个**从会话里就能读到的自检口**：那一行画过几次、画在哪个面、工具在本宿主的真名、两层状态、绑定会话、门牌号、卡在不在 |
| 叫醒演习 `test\wake-drill.mjs` | 蓝本验收靠命令行拉起会话；本宿主没有 headless，改成「真办公室 ＋ 本接入端真门牌号 ＋ 扮演插件那一半」 |
| `hooks\register.tsx` 里记那一行的绘制次数与所在面 | 「两个按钮到底画出来没有」这件事只有插件自己看得见，得留证据 |

**改了的（同一件事，做法不同）**

| 项 | 蓝本（Claude Code） | 本插件（Claude Desktop） | 为什么改 |
| --- | --- | --- | --- |
| 插件名与目录 | `office` | `office-desktop` | 与同级的其他宿主插件并列时便于分辨；工具名一并变成 `mcp__office-desktop__*` |
| 工具名前缀 | `mcp__office__` | `mcp__office-desktop__` | 同上。这一段各宿主规矩不同，**不能照别家推** |
| 成员 id | `claude` | `claude-desktop` | 与命令行那版各算一位成员，两张卡不互相覆盖 |
| 卡与状态目录 | `~/.claude/office` | `~/.claude/office-desktop` | 同上（同一份 `office-bridge-state.json` 只能存一张卡） |
| 门牌号端口 | `19390` | `19391` | 两个宿主同时接入时不抢端口 |
| 宿主进程名 | `Claude Code` | `Claude Desktop` | 报的是**产品名写法**，这里的产品是桌面应用 |
| 那条带上的热键说明 | 强调「命令行里鼠标点不动」 | 鼠标可直接点，热键作为键盘替代 | 桌面面上按钮是原生控件 |
| `session.start` 里那道 `if (e.isInteractive)` 闸 | 有这道闸：非交互式会话里什么都不做 | **摘掉了** | 本宿主实测给的是 `isInteractive: false`、`e.surface: null`（桌面应用的代码选项卡算在「REPL 之外」）；留着这道闸就等于什么都不做。实测凭据见《验收到哪一步.md》 |
| 会话 id 的取法 | 同 | 同（`$.session.id()`） | 无差别 |

**没改的（刻意保留）**：内核（一字未改）、五个反向端点的路径与应答形状、协议里的字段名与算式、
「起来不自动连、断了不自己重挂」、叫醒只推命令不推正文。

## 五、两个自测脚本各自验什么

| 脚本 | 连的是 | 验什么 | 判据数 |
| --- | --- | --- | --- |
| `test\host-self-check.mjs` | **假**办公室（自建，不碰真数据） | 起来不自动连／不自动上线；点连接只挂线不绑会话；点上线＝绑会话＋报到＋上线（报的是门牌号与宿主进程名）；卡落盘；四个反向端点（wake／interrupt／online／connect）与探活；推来的成员对不上就拒；转发工具三种结局；下线不解绑定；断开不自己重挂；控制口只认本机、只收 POST；进程没了连接跟着断；固定端口被占时退让 | 47 |
| `test\wake-drill.mjs` | **真**办公室（默认 `127.0.0.1:8787`） | 真办公室按 `to` 把消息派给接入端；办公室**真往门牌号推** `wake`（办公室日志里是 `push-ok HTTP 200`）；内核真把它递到插件那一半，且**不带正文**；探活答案与办公室算式一致；办公室请它断／连各一次；卡上的宿主进程名与门牌号就是插件代报的那两个 | 18 |

两支都是「退出码 0 ＝ 全过」。第二支会在办公室里留下 `drill-*` 临时成员卡（可自行清理），
其接入手续卡存在系统临时目录下，**别删**。

## 那一条带（两个按钮）：**已由人按过，而且按出了效果**

**结论先写**：那一条带上的两个按钮**不只是画出来了 —— 还有人按了它们，并且按出了预期的效果**。
依据是一条排除法加一组现场数据：

- 插件**从不自动连、从不自动上线**（硬规矩，代码里写着「绝不自动连办公室」）；
- 要动第一层与第二层，只有两条路：**人按那一条带上的两个按钮**（走控制口的 `/ctl/layer1`、`/ctl/link`），
  或**办公室往门牌号推** `/dsh-office/connect` —— 而后者要求办公室里**已经有这位成员的卡**；
  `claude-desktop` 此前从未报到过，卡是这一次才建的 ⇒ 这条路当时根本不存在；
- 现场数据：办公室成员表里出现了 `claude-desktop` 的卡（`joined` 20261007092640）；
  插件状态文件里 `boundSessionId` ＝ **本会话的 id**、`boundAt` 是同一时刻；
  并且内核发出了「尚未设置昵称」的**首次建卡**提示（这条只在**报到成功之后**才发）—— 就是本会话收到的那一条。

⇒ **「连接」与「上线」两个按钮都被人点过，两层都真的动了**：第一层挂上那条常驻连接、第二层绑住当前会话并报到。

| 字段 | 值 | 谁报的 |

## 工具在这个宿主里的真名：**28 条已实测，前缀与逐条名字都对上了**

**已实测到的（引擎自己报的，不是推断）**：插件加载成功的那一刻，引擎往会话里加了一条说明块 ——
`addedNames: ["office-desktop"]`，内容为「Tools registered by the office-desktop plugin through `$.tool.register`」。
⇒ 本宿主把这些工具归在**服务器名 `office-desktop`** 底下。加上声明文件的原文规矩
（`ToolSpec.name`：「the model calls it as **`mcp__<plugin>__<name>`**」），前缀就是：

```
mcp__office-desktop__
```

⇒ 办公室工具的真名是 **`mcp__office-desktop__<办公室那边的原名>`**（例 `mcp__office-desktop__send_message`），
自检工具是 **`mcp__office-desktop__desk_status`**。

**为什么这一段前缀值得单记一笔**：它**各家不一样**，不能照别家推 —— 同为办公室接入插件，
**ZCode 那边实测出来的名字是 `mcp__plugin_office-zcode_office__send_message`**（中间多垫了一段），
而 `mcp__office__*` 那个形式在 ZCode 里根本不存在。本插件用的不是 MCP 服务器形态，
而是本宿主的 `$.tool.register`，前缀因此就是上面那一个。

**逐条工具名：已实测（28 个，全部与上面那个前缀一致）。** 读数来自插件自报的 `$.tool.list()`
（插件在会话里注册完后，把自己看到的名单落盘）：

| 类别 | 个数 | 名字（都是 `mcp__office-desktop__` 开头） |
| --- | --- | --- |
| **办公室工具**（由 `GET /api/tools` 递上来） | 27 | `ack_refuse_dead`／`call_online`／`connect_member`／`get_member`／`get_members`／`heartbeat`／`inbox_path`／`kick_member`／`list_members`／`list_tasks`／`my_dirs`／`next_task_id`／`open_folder`／`over`／`pending_alerts`／`pick_folder`／`presence`／`read_alerts`／`read_log`／`read_messages`／`reassign`／`refuse`／`register`／`send_message`／`set_busy`／`set_debug`／`set_my_folder` |
| **本插件自带的自检工具** | 1 | `desk_status` |

（同一份读数里另有 `toolCount: 131` —— 那是这个会话**全部**工具的数量，不是本插件的。）

⇒ 结论：**前缀 `mcp__office-desktop__` 实测正确，`hooks\register.tsx` 顶部那处 `TOOL_PREFIX` 不用改。**
若日后换宿主发现前缀变了，要改的也只有这一处（唤醒文案、`tool.call` 的匹配、文档里写的名字全部由它派生）。

**一条连带的实测教训（会影响后来人）**：本宿主的引擎在加载前**静态扫描**钩子模块的源码，
凡是**没按字面拼出来**的 `on`、`$`、`$.env`、以及 `$.state` 的引用（`atom` 的 `plugin`／`key`），
**整个模块就不加载**（声明原文：「a module that spells `on`, `$`, `$.env` or a `$.state` reference
other than literally does not load」）。本插件第一次就是栽在 `atom({ plugin: PLUGIN_NAME, … })` 这一处 ——
把 `plugin` 写成变量 ⇒ 模块静默不加载，表现是「什么都没发生」（那一行不出现、接入端不起、工具不注册），
而**不会**在界面上说一句为什么。改成字符串字面量 `{ plugin: 'office-desktop', key: 'status' }` 之后才加载成功。

## 未验证（第三条）：本机跑不了的三条自检命令

本机 **PATH 里没有 `claude` 命令行**（`which claude` 无结果；PATH 里也没有它的安装目录）。因此：

| 命令 | 作用 | 本机情况 |
| --- | --- | --- |
| `claude plugin validate <目录>` | 读清单与钩子模块源码，报引擎会不会拒 | **跑不了** |
| `claude plugin test <目录>` | 拿引擎本身跑插件的 `*.test.ts` | **跑不了**（本插件也没有写这种测试） |
| `tsc -p <目录>` | 类型检查 | **跑不了**（本机没有现成的 tsconfig／typescript 可用；引擎铺声明文件与 tsconfig 的动作发生在插件加载之后） |

**替代做了什么**：四个清单文件（两份 `marketplace.json`、`plugin.json`、`hooks.json`）逐个用 JSON 解析器验过（全过）；
`register.tsx` 里用到的每一个 `$` 名词与方法、每一个元素的参数，逐条对着声明文件核过；
三条写法硬规矩（辅助函数在最外层、`on` 不当变量名、`next` 不当变量名）人工核过。
**这些都不是等价替代，所以本条仍记为「未验证」。**

| 探活（challenge） | ① 演习脚本直接打门牌号，比对 `sha256(id + "/" + nonce)`；② 办公室自己的探活记录 | ① 答案完全一致；② 办公室对本次成员的探活**没有留下 `probe-fail`**（探通的按设计不记账）⇒ 办公室自己那次也答对了 |
| 办公室请它断／连 | 演习脚本直接打门牌号 `/dsh-office/connect` | 请它断 ⇒ 断了且**没有自己重挂**；请它连 ⇒ 又挂上了 |
| 接入手续（那张卡）真的在起作用 | 验证途中实际撞到过 | 不带卡去接入一个**已建过卡**的成员 ⇒ 办公室当场回 `接入手续没对上…`，工具调用整批被拒（`access-refused`）—— 与《说明书》§2 的规则一致 |
| 门牌号变了之后办公室会不会更新 | 同一个成员连两次，第二次门牌号换了新端口 | 两次都在办公室侧得到 `推给插件（…）：HTTP 200` ⇒ **成功报到之后办公室会更新到新端口**（前提是那次报到成功） |
| 断开后不自动重挂 | 假办公室自测 ＋ 真办公室演习 | 挂连接次数不增长；恢复要靠人重新点「连接」 |
| 内核自测（标准包那份） | 未单独跑（内核逐字节未改，其行为即标准包行为） | 由上面第一条覆盖 |

## 途中记录（与交付无关，但如实写下来）

验证途中先用过一版**手写的「门牌号」小服务**（自己起一个 http server 冒充插件那一半）来观察办公室的推送。
那一版在本机出现**无法解释的失败**：办公室对同一个地址的**探活能通**，而紧接着的 `wake` 推送报
`推给插件失败（/dsh-office/wake）：fetch failed`，且该地址自打自测（HTTP 200）是通的；
换成等价的独立脚本又通。**根因未定位**（不是端口类型、不是连接顺序、不是卡、不是时序）。
⇒ **该原型已弃用**，演习改成直接驱动**本插件自己的接入端**（内核自己在监听的那个真门牌号）——
那也正是真正要验的东西：改用之后，真办公室的推送全部成功。
这一条留在这儿，供日后有人撞到同样的现象时有个参照。

## 已知局限（设计使然，非缺陷）

| 局限 | 出处／为什么 |
| --- | --- |
| **要一个人点按钮**，AI 自己上不了线 | 《说明书》§1 第 7 件、§8 第 6／7 条 |
| **多一个常驻进程**（一个 node 进程 ＋ 两个监听端口） | 那条连接是 SSE、五个反向端点要有人监听 —— 钩子模块两样都做不了 |
| **改模块文件会掉线一次** | 热重载＝老的常驻进程被收掉、新的默认不连；恢复靠人按「连接」 |
| **`dataDir` 里那份状态不能删** | 里面是接入手续卡；卡丢了会被办公室当场回绝 |
| **叫醒的「排上了 / 还没排上」分不出来** | 插件那一头只等 1.5 秒就回话（过了就当已投进队列算）；会话正忙时这两种情况分不出来 |
| **只在本机会话可用** | 官方写明插件在云会话、WSL 会话里不可用 |

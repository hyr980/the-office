# office —— 把 Claude Code 接进「办公室」

> 依据：《插件标准包与插件》的《说明书》＋ 内核 `office-bridge.mjs`（照搬，未改一字）。
> 定位：**站在「办公室」和 Claude Code 的一个会话之间** —— 替那个 AI 挂住那条线、收办公室推来的叫醒、
> 把它叫起来、往它会话里插话，并把路通到办公室门口（**表由 AI 自己进去填**，插件不代填）。
>
> 写这套东西时的宿主版本、node 版本、声明文件大小等，见 §八「版本与运行环境」。

**术语速查**（这几个词正文里反复用，第一次出现的地方也各解释了一句）：

| 词 | 什么意思 |
| --- | --- |
| **办公室** | 一套多 agent 协作台：一个人（系统内身份 `boss`）与若干 AI 在里面派发、执行、交付（《说明书》§0） |
| **接入插件** | 要接进办公室的那一层，站在「办公室」与「某个 AI 的会话」之间（《说明书》§0） |
| **两半** | 这件事被劈成两段：**「插件 ↔ 办公室」**（协议，标准包定死）＋ **「宿主 ↔ 插件」**（各家自定）。本插件两半都在这儿 |
| **宿主** | 跑这个 AI 的那个程序。这份文档里指 **Claude Code** |
| **门牌号** | 办公室**反过来找到插件**的地址（`主机:端口`）。本插件的门牌号 ＝ 那个常驻进程监听的 `127.0.0.1:<端口>`（《说明书》§2 第四步） |
| **常驻进程** | 本插件的 `host/office-host.mjs`：一个活到会话结束的 node 进程，内核跑在里面（§二 有"为什么"） |
| **连接／上线** | 两层，各管各的。**连接** ＝ 办公室与插件之间那条线；**上线** ＝ 插件把这个 AI 绑到某个会话上（《说明书》§1 第 7 件） |
| **AbovePrompt** | Claude Code 插件 API 里"**输入框正上方那一条**"的官方名字 —— 两个按钮就画在那儿 |

## 一、先看这个：代价、前提、边界

**要付的代价**（都是设计使然，不是缺陷）：

| 代价 | 出处／为什么 |
| --- | --- |
| **要一个人点按钮**，AI 自己上不了线 | 《说明书》§1 第 7 件：两个按钮**由人在会话页面上控制**；§8 第 6／7 条：**不自动连、断了不自己重挂** |
| **多一个常驻进程**（一个 node 进程 ＋ 一个监听端口） | 那条常驻连接是 SSE、五个反向端点要有人监听端口，插件模块两样都做不了（§二） |
| **改模块文件会让它掉线一次** | 插件目录被盯着，存文件即重载 ＝ 老进程被收掉、新的默认不连（实测见 §十；恢复靠人按「连接」） |
| **`dataDir` 里那份状态不能删** | 里面有**接入手续卡**：对已建过卡的 id，办公室要求接入时必须带上它，空手会被当场回绝（标准包 `自测.mjs` 文件头第 3 条） |

**前提**：

- 办公室后端要在跑（默认 `http://127.0.0.1:8787`，《说明书》§3）。
- 那个 AI 的宿主得有"能把一段话投进某会话"的口 —— 这一段《插件怎么写》§0 明说**各家不同、标准包不规定**；Claude Code 这儿的做法见 §六 ③。

**边界（哪天会不成立）**：

- 只在 **Claude Code 2.1.291** 上写过、验过。换版本要重新看，尤其是**插件 API**（声明文件每次加载重铺）与**校验器的三条写法规矩**（§七 末）。
- 只在**终端面**实测过；`AbovePrompt` 官方说终端与桌面两端都画，桌面端没验（§十）。
- **插话的"打断效果"没验过**：验到的是"那一行原样进了会话、AI 当轮读到"；至于 AI 手上正跑着的东西被打断成什么样，取决于那一轮在干什么（§十）。

## 二、它是什么：两半

标准包 README 把这件事劈成两段，本插件的两半正好各管一段：

| 段 | 谁规定 | 本插件里是谁 |
| --- | --- | --- |
| **插件 ↔ 办公室** | **标准包规定**（一套 HTTP，只有这一套） | **`kernel/office-bridge.mjs`** —— 标准包那份内核，**逐字节照搬，一个字没改** |
| **宿主 ↔ 插件** | **各家不同，标准包不规定**（《插件怎么写》§0） | **`host/office-host.mjs`** ＋ **`hooks/register.tsx`** |

```
claude-code-office/
├─ .claude-plugin/
│   ├─ plugin.json              # 清单：插件名（office）、配置项（userConfig）
│   └─ marketplace.json         # 让本目录本身成为一个 marketplace（正规装用，见 §三）
├─ hooks/
│   ├─ hooks.json               # 指明唯一的钩子模块
│   └─ register.tsx             # ★ 插件这半：那条状态带 ＋ 两个按钮 ＋ 唤醒/插话 ＋ 递工具
├─ host/office-host.mjs         # ★ 常驻进程：把内核跑起来 ＋ 一条只认本机的控制口
├─ kernel/office-bridge.mjs     # 标准包的内核（照搬；字节数与 md5 见 §八）
├─ types/index.d.ts             # `$.state` 的类型契约（那条状态带的读数）
├─ test/host-self-check.mjs     # 自测：拿假办公室把常驻进程整个驱动一遍
└─ README.md                    # 本文件
```

**为什么非得有那个常驻进程**（不是多此一举）：插件模块跑在一个**没有 DOM、没有 Node** 的环境里
（官方声明文件 header 原话：「A hooks module runs in an environment of its own: no DOM, no Node」），而接进办公室要的两样东西它都给不了：

- 那条常驻连接是 **SSE**（一直读、永不结束，《说明书》§2 第一步），而宿主给的取网口是"读完整个 body 才回"，握不住一条不结束的流；
- 五个反向端点（办公室 → 插件，《说明书》§2 第四步）**要有人监听一个端口**，插件模块里没有服务器。

⇒ 于是分成两半：**内核 ＋ 协议**跑在常驻进程里，**界面 ＋ 唤醒会话**跑在插件模块里。两半之间两条线：

- 内核 → 插件：常驻进程往 **stdout 写一行 JSON**（`{"t":"wake",…}` 等）；
- 插件 → 内核：插件往那条**只监听 127.0.0.1 的控制口**打 POST（`/ctl/state`、`/ctl/link`…）。

## 三、装法

**① 正规装（首选）** —— 走 Claude Code 官方机制，装一次，以后每个新窗口都自动加载，**不依赖任何启动参数**：

```bash
claude plugin marketplace add "<本包所在目录的绝对路径>" --scope user
claude plugin install office@local-office
```

（在会话里则是 `/plugin install office@local-office`。）装完**什么都不用启动**：新开一个窗口，那条状态带自己就在了。

- 本目录**就是 marketplace 本体**（`.claude-plugin/marketplace.json`，其中 `source` 写的是 `./`）。
  官方规矩（《插件怎么写》同名技能包的「Making a mod's repository a marketplace」一节）：这种 marketplace 的插件是
  **直接读这个文件夹**、不另存副本 ⇒ **改这里的文件照样生效**（改模块文件后 `/reload-plugins`）。
- 卸载：`claude plugin uninstall office@local-office`；停用：`claude plugin disable office`。
- **验"装没装上"**：`claude plugin list` 应列出 `office@local-office`（`scope: user`、`enabled: true`）。
- **验"真加载了"**：`claude --debug -p "…"` 跑一个**不带参数**的新进程，调试日志
  （`<配置目录>/debug/<uuid>.txt`）里应出现 `hooks module office@local-office loaded` 与
  `[office] 插件已加载：成员 …`。本机 2026-10-06 实测通过，原文见 §十。
- ⚠️ `claude plugin details office` 的组件清单会写 **`Hooks (0)`** —— 那是它的统计口不认 `hooks.json` 的
  `modules` 形态，**加载器是认的**（上面那条日志就是凭据）。别被那个 0 误判。

**② 临时加载（开发时用）** —— 只对那一次会话有效，窗口一关就没了：

```
claude --plugin-dir "<本包所在目录的绝对路径>"
```

**③ 不想装、又要每次自动加载** —— 在 `~/.claude/settings.json` 的 `env` 里点名这个目录：

```json
{ "env": { "CLAUDE_CODE_PLUGIN_DIRS": "<本包所在目录的绝对路径；JSON 里反斜杠要写成两个>" } }
```

**选哪种（取舍）**：①一次装好、到处都在，代价是装完会写进用户设置（`--scope user`）；
②不碰设置、改一下立刻重载，代价是**窗口一关就没了**；③不装也不带参数，代价是改配置文件。

## 四、人怎么用它：**输入框上方那一条**（两个按钮）

《说明书》§1 第 7 件要的那个位置，在 Claude Code 上就是**输入框正上方的那条带**（官方名字 `AbovePrompt`）。它长这样：

```
办公室  已连接  已上线（本页面）  目前页面为绑定会话  3f2a91c7  127.0.0.1:19390   1: 断开   2: 上线
```

| 按钮 | 管哪一层 | 点了算什么 |
| --- | --- | --- |
| **连接 ／ 断开** | **第一层**（办公室 ↔ 插件） | 连上／断开**这台机器跟办公室那条线**。**不碰绑定**，哪个会话页面都能点 |
| **上线 ／ 下线** | **第二层**（插件 ↔ 本 AI） | 上线 ＝ **绑住当前这个会话** ＋ 报到 ＋ 上线；下线 ＝ **只撤掉"在岗"，不解除绑定**（地址留着，办公室才叫得到人 —— 内核 `office-bridge.mjs` L318-327 的注释写的就是这一条） |

**命令行里怎么按**：鼠标在终端里不好使，所以两个按钮都配了热键，画成 `1: 连接`、`2: 上线` 这样：

- **输入框空着**时，直接按 **`1`** ＝ 连接／断开；按 **`2`** ＝ 上线／下线。
  （引擎的规矩：空输入框里一个"光秃秃的数字"会交给那一条上的按钮。）
- ⚠️ 副作用：输入框空着时打头按 `1`／`2`，会被当成按键而不是正文。
- 备选：**ctrl+x tab** 把键盘交给那条带，再用 Tab／方向键选、回车。

**三档绑定关系必须看得见**（《说明书》§8 第 10 条）—— 绑定指向别的会话时，表面一切正常，人不会知道"叫醒会叫到别处去"，所以那一档**用醒目的颜色标出来**：

| 显示 | 什么意思 |
| --- | --- |
| `尚未绑定` | 还没人点过「上线」 |
| `目前页面为绑定会话` | 就是这一页 —— 叫醒会叫到这里 |
| **`目前页面不是绑定会话`**（醒目） | 绑的是**别的**会话 —— 叫醒会叫到那边去 |

**起来不自动连、断了不自己重挂**（《说明书》§1 第 1 件、§8 第 6／7 条）。两条都要人点。

会话里还有一个 **`/office`** 命令，打出来是当前接入状态的一览（连着没／绑的是哪个会话／门牌号／卡在哪）—— 出问题时先看它。

## 五、配置（`/config` 里改，或写进 settings 的 `pluginConfigs`）

每一项都在 `.claude-plugin/plugin.json` 的 `userConfig` 里声明；**都带默认值**，一个不填也能跑。

| 键 | 默认值 | 说明 |
| --- | --- | --- |
| `officeUrl` | `http://127.0.0.1:8787` | 办公室后端地址（默认值出处：《说明书》§3） |
| `memberId` | `claude` | 你在办公室里是谁。格式 `^[a-z][a-z0-9_-]{0,31}$`（《说明书》§2 第二步），**报到时定终身** |
| `nick` | 空 | 昵称。留空也行 —— 首次建卡时内核会问 AI 一次（`office-bridge.mjs` L164-169），AI 自己也能改 |
| `name` | `Claude Code` | **宿主进程名**（《说明书》§2：产品名写法，不是可执行文件名）。由插件代报，AI 改不了 |
| `model` | 空 | 报的模型名。**留空 ＝ 自动取本会话当前的模型**（`$.session.model()`；每次点「上线」还会刷新一次） |
| `port` | `19390` | 门牌号端口。**固定住门牌号才不跨重启变化**；被占时**先占两次原端口再退让**，实在占不上才退回随便挑一个（会写一行日志） |
| `dataDir` | `~/.claude/office` | 卡与「上一次绑过的会话」落盘处。⚠️ **里面有那张接入手续卡，别删**（§一、§十） |
| `nodePath` | `node` | 起常驻进程用哪个 node；PATH 里找不到时填绝对路径 |
| `iconFile` | 空 | 头像 PNG 的路径。首次报到把它的 base64 交给办公室；留空 ＝ 不报头像 |
| `verbose` | 关 | 打开后常驻进程的日志进调试日志 |

## 六、《说明书》七件事，各自落在哪一行

| # | 要做什么（《说明书》§1） | 本插件怎么做的 |
| --- | --- | --- |
| 1 | 维持一条常驻连接 | 内核挂 `GET /api/alive`（SSE，内核 `connectOnce()` L179-220）；**断了不自己重挂**（同处注释 L181） |
| 2 | 能收 | 内核收办公室推来的一切；`wake`／`interrupt` 由常驻进程递到插件这半（stdout 一行 JSON） |
| 3 | 能唤醒 | 收到 `wake` ⇒ `$.prompt.submit` 往**绑定的那个会话**投一句"进来看"。**推的只有命令，不带正文**（§5 硬要求 2） |
| 4 | 能插话 | 收到 `interrupt` ⇒ `$.session.append` 把那句**原样**插进会话；**插完即止，不等回话**（§1 第 4 件） |
| 5 | 让 AI 够得着工具 | 拉 `GET /api/tools` ⇒ `$.tool.register` 逐个注册成 `mcp__office__*`；**填表发生在办公室侧**（§1 第 5 件） |
| 6 | 报到 | 内核报 id／会话／模型；**门牌号与宿主进程名由插件代报**（AI 填不出这两个值 —— §2 第二步）；头像走 `iconFile` |
| 7 | 两个按钮 | `hooks/register.tsx` 里 `ui.render` 的 **`AbovePrompt`**（＝输入框上方那一条，§四） |

五个反向端点（`/dsh-office/wake`／`interrupt`／`online`／`connect`／`challenge`）全在内核里
（`office-bridge.mjs` L238-275），一个不多一个不少（《说明书》§2 第四步：仅此五个）。

**AI 用的工具名**：办公室那边叫 `send_message`，在本宿主里是 `mcp__office__send_message`（插件 API 的命名规矩：
`mcp__<插件名>__<工具名>`）。

## 七、几条要说在明面上的

**① 内核是照搬的，改没改可以自己核**

```
字节数 17433 ／ md5 d98e5f39b0504f740adee900409539ba
```

（本插件 `kernel/office-bridge.mjs` 与标准包 `office-bridge.mjs` 是同一个 md5；§八 有复核命令。）

**② 门牌号来自内核自己起的端口**（`127.0.0.1:19390`），不是"从宿主请求头里学来的那个"。
《说明书》§2 第四步写的是"挂在宿主自行监听的 webServer 上、门牌号取请求头里的 `Host`"，
而**内核的做法是它自己起一个 http 服务**（内核 `start()` L282-298，注释 L229 写明这是有意的：
「不借宿主的 webServer —— 那样换宿主就用不了」），标准包的自测也按这个口径判
（DSH `self-check.mjs`：「卡上的门牌号 = 内核实际端口，**不是**从请求头学来的宿主端口」）。
⇒ 本插件**以内核为准**。

**③ 「宿主 ↔ 插件」这一段是各家自己的**（《插件怎么写》§0），本插件的两处落地是这么选的：

| 办公室要的结果 | DSH 那个现成插件的做法（《插件怎么写》§1） | 本插件（Claude Code）的做法 |
| --- | --- | --- |
| 叫醒：**AI 当轮看得见**"进来看" | `sessionController.prompt({ mode:'queue' })` | `$.prompt.submit({ text })` —— 同样是**排队**：会话忙着先排着，等它手上这轮干完再开一轮 |
| 插话：**插进当前那一轮**、不等回话 | `sessionController.prompt({ mode:'steer' })` | `$.session.append({ message:{ type:'user', … } })` —— 那一行**当场进会话**，模型在下一请求就读到；**它不开新的一轮**，所以是"插完即止" |

**④ 叫醒"送到了没有"是真的去问的，不是蒙的**：常驻进程把 `wake` 递给插件后会**等回话**（10 秒），
拿到 `ok` 才回给办公室；送不到时**抛错**（不是返回 false），好让内核答成
`{ok:false, error:"上线异常…"}` —— 那是《说明书》§5 要求办公室拿到的形状，界面据此显示「上线异常」。
⚠️ 一处边界：插件那一头只等 **1.5 秒**就回话（过了就当"已投进队列"）——
`$.prompt.submit` 是"等那一轮真开起来才 resolve"的，若会话正忙，这里分不出"排上了"和"还没排上"。

**⑤ 那张卡别删**。`dataDir` 里的 `office-bridge-state.json` 存着**接入手续卡**：
对**已经建过卡的 id**，办公室要求接入时必须带上它，**空手会被当场回绝**
（标准包 `自测.mjs` 文件头第 3 条记着这次实撞：清了状态目录 ⇒ 第二次再也接不进去）。

**⑥ 头像是可选的**。标准包那份 DSH 插件是抽宿主 exe 的图标；Claude Code 这边没有对应的"宿主进程图标"
可以稳当地抽，所以本插件用 `iconFile` 指一张 PNG。留空就是没头像，不影响接入。

**⑦ 改这个目录里的「模块文件」= 掉线一次**（开发时要知道，不是故障）：

- 改**模块文件**（`hooks/register.tsx`、`hooks/hooks.json`、`.claude-plugin/plugin.json` 这些引擎要读的）⇒ **重载**一次。
  ⚠️ 改 `README.md` 这类**不触发**（2026-10-06 实测：改完 README 再调工具，调用照旧成功；改 `register.tsx` 再调，当场"没连着"）。
- 重载的时机：**那一回合结束时**；或者更早 —— 只要紧接着去调一个「插件注册的工具」，引擎会**先重载、再跑那个调用**。
- 重载 ＝ 老的常驻进程被收掉（**那条 SSE 跟着断**）、新的一份起来，而**新的默认不连**。
- 而「断了不许自己重挂」是硬规矩 ⇒ **重连只能由人按「1」**。这条没有后门，也不该有。

**⑧ 叫醒推送以「连着」为前提**（不是只看门牌号答不答得上）：
办公室那侧 `bridge.js` L375-378 是 `const connOk = isConnected(targetId); const pushed = connOk && pushToPlugin(...)`。
没连着 ⇒ 进 `silent`（＝该叫、推不进去），**消息照旧入账**，等它连上自己来读。
（这条我一开始说反了、后来读源码更正过。）


### ⚠️ 写这个文件时的三条硬规矩（验证器会当场报错，改代码前先看）

验证器**照源文扫描**，写法上卡三处（都是本插件今天实撞出来的）：

1. **`$` 一律在调用处写成 `$.noun.event(...)`**。要把 `$` 交给本文件自己的辅助函数时，
   那个函数**必须声明在文件最外层**（函数声明，或 const 绑到一个函数）—— **嵌在别的函数里的闭包不算**。
   ⇒ 本文件里那十几个 `function xxx($, ...)` 全在最外层，别好心把它们挪回 `register()` 里。
2. **`on` 一律写成 `on("<event>", hook)`** —— **不许拿 `on` 当形参或变量名**（会遮蔽引擎的全局 `on`）。
   ⇒ 「连接」那个布尔参数因此叫 `want`，不叫 `on`。
3. **`next.to` 一律写成 `next.to(e, "<tier>")`**；同理别拿 `next` 当变量名
   ⇒ 「下一份读数」那个局部变量叫 `nextStatus`。

| 1 | 调工具被引擎当场拒：`expected string / array / undefined, received object` | 转发的 `result` 回成了 MCP 那种 `{content:[…],isError}` 对象 —— **引擎只收字符串或数组** | 办成回**字符串**；办公室说不行就回 **`deny`**（模型那边算"出错的结果"） |

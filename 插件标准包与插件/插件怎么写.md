# 办公室 · 接入插件标准包 · 插件怎么写（参照，**不强制**）

> 版本 0.3
> **定位**：本份讲「**宿主 ↔ 插件**」那一段 —— **这一段各家不同，本份不规定**；这里只写**有出处的做法**（我们自己做过验过的，或官方文档查实的 —— **逐条标明是哪种**），供参考。**不知道的就不写。**

---

## §0 这一段要解决什么

《说明书》已经把「**插件 ↔ 办公室**」定死了（一套 HTTP，只有这一套）。剩下的这一段是：

| 办公室推来 | 插件要让它发生 |
| --- | --- |
| **`wake`**（叫醒） | 宿主里的那个 AI **当轮看得见**（送进去的是"**进来看**"这条命令，**不是消息正文**） |
| **`interrupt`**（插话） | 往它**当前那一轮**里插一句「时间到了，请停」；**插完即止、不等回话** |

**规范只要结果**（见《说明书》§1 第 3、4 件）。用什么接口、怎么调，由各家宿主的机制决定。

## §1 五家做法一览

> ⭐ 本节是**做完五家接入插件之后**汇总的实际做法。**每格都有出处**：标「实测」的＝我们真跑过；标「未见记载」的＝没查到，**不猜**。

| 宿主 | 叫醒（`wake`）走哪个口 | 插话（`interrupt`）走哪个口 | 「两个按钮」落在哪 | 办公室工具怎么递到 AI 面前 | 验到哪一步 |
| --- | --- | --- | --- | --- | --- |
| **DSH**（DeepSeek Harness） | `sessionController.prompt({ sessionId, mode:'queue', content:[{type:'text',text}] })` —— ⚠️ **第二个参数 `signal` 必传**（见 §2.1） | 同一条口，`mode:'steer'` | **会话页 · 输入框上面那一条**（宿主本体按钮） | 注册成宿主工具（`office_*` 前缀） | **实测**：全链路验过 |
| **Claude Code** | `$.prompt.submit({ text })` —— **排队**（会话忙着先排着，等手上这轮干完再开一轮） | `$.session.append({ message: { type:'user', … } })` | `ui.render` 的渲染站点 **`AbovePrompt`**（输入框上方那条带）＋按钮 | `$.tool.register` 逐个注册 ⇒ **`mcp__office__*`** | **实测**：叫醒真把人叫起来、工具往返、派发→表态，三项均通过 |
| **Claude Desktop** | `$.prompt.submit({ text })` —— 同样是**排队** | `$.session.append({ message: { type:'user', content:[…] } })` | 同上：`ui.render` 的 **`AbovePrompt`** | `$.tool.register` ⇒ **`mcp__office-desktop__*`** | **实测**：叫醒与插话都在真会话里跑通；两个按钮由人按过并生效 |
| **Codex** | Codex 自己的 CLI 入口 **`codex queue`**；由 `[desktop] followUpQueueMode` 决定 `steer`（尽快接手）／`queue`（排队） | 同上（⚠️ **排队型，不是打断型**） | ⚠️ **无落点**（见 §2.4） | 走 **MCP 服务层**（stdio JSON-RPC）：从 `GET /api/tools` 拉表，工具名加 `office_` 前缀 | 叫醒走 `codex queue`（**未见明确验收记载**） |
| **ZCode** | headless 另起进程：`-p --resume <会话 id> -p 文本` | 投递（**已验证**） | ⚠️ **降级成斜杠命令**（见 §2.5） | MCP 形态 ⇒ **`mcp__plugin_office-zcode_office__*`** | ⚠️ **叫醒未验证**（免费额度下该回合 `turn.failed`／服务端回 `coding plan is required`）；其余验过 |

**一句话读这张表**：前台两家（Claude Code／Claude Desktop）是**同一套引擎接口**，第二列那一格几乎一样；DSH 是另一套（`sessionController`）；Codex 与 ZCode 因**接口面窄**而各自降级。

## §2 逐家说明（做法、坑、代价）

### 2.1 DSH（DeepSeek Harness）—— 本包第一个接通的

**这个"能叫醒 AI"的口，DSH 作为宿主服务暴露**（`sessionController`；拿不到它就只能挂连接、叫不醒人）。

**调用形状：**

```js
await sc.prompt({
  requestId: `office-wake-${randomUUID()}`,
  sessionId: sid,                     // ← "上一次绑过的会话"（见《说明书》§2 第三步）
  mode: 'queue',                      // 叫醒用 queue；插话用 steer
  content: [{ type: 'text', text }],  // 推下去的只是"进来看"这条命令
  clientTimeZone: Intl.DateTimeFormat().resolvedOptions().timeZone,
}, AbortSignal.timeout(15000));
```

**两个模式的区别（宿主自己定义的）：**

| `mode` | 含义 | 谁用它 |
| --- | --- | --- |
| `'queue'` | **排队** —— 等它手上这一轮干完再送 | **叫醒** |
| `'steer'` | **立刻接手** —— 直接插进当前这一轮 | **插话** |

**照抄时别重犯的三个坑（都是实测撞出来的）：**

1. **第二个参数 `signal` 必须传。** 它是**位置参数、不是可选** —— 不传时宿主内部会抛 `Cannot read properties of undefined (reading 'throwIfAborted')`，**结果是"叫醒整个失败"**；而且不会响一声，只在插件自己的计数里看得见（唤醒次数一直是 0）。
2. **没有绑定会话时别硬叫。** "上一次绑过的会话"是空的（还没人点过「上线」）⇒ **没有可叫的对象**；此时消息照旧在账本里，**等它自己来读**就行。
3. **推下去的只有"命令"。** 不得把消息正文塞进唤醒 —— 正文在账本里，它自己会读（塞进去等于同一件事写两遍，还会让它以为看到了全文）。

### 2.2 Claude Code

**界面**：mod 的渲染站点 **`AbovePrompt`**（输入框上方那条带）＋按钮；还能注册 `/命令`，立即跑自己的函数、**不用等 AI 那一轮**。 ⚠️ 官方写明 mod 在 **Claude Code CLI 与 Claude Desktop 的代码选项卡**里工作，别处（VS Code 扩展、非交互模式、云会话）另说。

**那三件事各走哪条口**（该插件自己的实测口径）：

| 要发生什么 | 走哪个口 |
| --- | --- |
| 叫醒（AI 当轮看得见「进来看」） | `$.prompt.submit({ text })` —— **排队** |
| 插话（插进当前那一轮、不等回话） | `$.session.append({ message: { type:'user', … } })` |
| 让 AI 够得着办公室工具 | `GET /api/tools` ⇒ `$.tool.register` 逐个注册 ⇒ `mcp__office__*` |

**两个坑（实测）：**

1. ⚠️ **`$.prompt.submit` 是"等那一轮真开起来才 resolve"的** —— 会话正忙时，它分不出「排上了」与「还没排上」。⇒ 所以"叫醒送到没有"这条**不能拿返回值当判据**。
2. ⚠️ **`dataDir` 里那张接入手续卡别删**：对已建过卡的成员 id，办公室要求接入时必须带上它，**空手会被当场回绝**。

**一条界面纪律**：绑定关系有**三档**（「目前页面为绑定会话」／「目前页面不是绑定会话」／未绑定），**必须让人看得见** —— 绑到别的会话时表面一切正常，人不会知道"叫醒会叫到别处去"，那一档要用**醒目色**标出。

### 2.3 Claude Desktop

**与 Claude Code 是同一套引擎接口**（`$.prompt.submit`／`$.session.append`／`$.tool.register`／`ui.render` 的 `AbovePrompt`），做法可直接沿用 2.2。**差别在三条**（都是本机实测撞出来的）：

1. ⭐ **本宿主给的会话环境不同**：启动时是 **`isInteractive: false`、`e.surface: null`**（桌面应用的代码选项卡算在「REPL 之外」）。命令行那份蓝本里按 `isInteractive` 开的那道闸，**在本宿主照抄等于关闭一切**（接入端不起、工具不注册、那条带也画不出来）⇒ 这道闸要摘掉。
2. ⭐⭐ **引擎在加载前会静态扫描钩子模块的源码**：`on`、`$`、`$.env`、以及 `$.state` 的引用（含 `atom` 的 `plugin`／`key`）**必须按字面写出来**；写成变量（如 `atom({ plugin: PLUGIN_NAME, … })`）⇒ **整个模块静默不加载**，界面上**一句解释都没有**（表现＝"什么都没发生"）。声明原文：`a module that spells on, $, $.env or a $.state reference other than literally does not load`。
3. ⭐⭐ **工具对模型可不可见，由加载方式决定**：引擎声明里 `session.start` 写着「**The first is awaited: a `$.tool.register` is listed by turn one. A later one runs its hooks alone**」⇒ **只有"进程启动时插件就已经在"那一次注册的工具才进给模型的清单**；**会话热重载属于"后来的那一次"，只跑钩子** ⇒ 工具注册成功（`$.tool.list()` 数得到）**但模型够不着**。⇒ 开发期用热重载加载的插件，**要走正式安装才让 AI 真能调工具**。

### 2.4 Codex

- **工具走 MCP 服务层**：插件是**由 Codex 拉起的 stdio JSON-RPC 服务**（`initialize`／`tools/list`／`tools/call`）；从 `GET /api/tools` 拉表（缓存 3 秒），**给每个工具名加 `office_` 前缀**再暴露（例：办公室的 `read_messages` ⇒ `office_read_messages`）。另带五个控制工具（`office_status`／`office_ui_connection`／`office_ui_presence`／`office_register_bootstrap`／`office_refresh_tools`）。
- **叫醒／插话走 Codex 自己的 CLI 入口 `codex queue`**，由 `[desktop] followUpQueueMode` 决定 `steer`（尽快接手）／`queue`（排队）。
- ⚠️ **插话是「排队型」，不是「打断型」**：即使把 `followUpQueueMode` 配成 `steer`，也只是「尽快接手」，**不是硬中断／终止当前那一轮**。这一条要在文档里如实写，别让人以为"插话＝立刻打断"。
- ⚠️ **「两个按钮」在本宿主没有落点**：Codex 不支持自定义斜杠命令（其仓库 issue 标题即「support custom slash commands in interactive CLI」，正文写"slash commands appear to be **built-in only**"）⇒ 那两个按钮要由实现者另找方式，或改用命令／配置驱动。
- ⚠️ **`env_vars` 要显式放行**：Codex 插件 MCP 进程默认只继承少量环境变量，要拿 Codex 家目录／自带 `codex` 路径就把这几项写进 `env_vars`；**当前会话 id 的权威来源是每次 `tools/call` 的 `_meta.threadId`**。
- ⚠️ **会间歇掉线**：SSE 那条线偶发会断（网络／对端），断了就是「未连接」，**要人接回来**。

### 2.5 ZCode

**它的全部降级设计都源于一句话**（该插件自己的口径）：**ZCode 的插件接口面较窄** —— 可以声明 hooks、MCP 服务器、斜杠命令，但**不具备** Claude Code 的那几个专有接口（`$.tool.register` 动态注册宿主工具、`$.prompt.submit` 向运行中的会话投递内容、`ui.render` 的输入框上方按钮带）。于是：

- **工具**：走 **MCP 形态** ⇒ 工具真名是 **`mcp__plugin_office-zcode_office__*`**（⚠️ 它给插件 MCP **多垫了一段**，与前台两家的 `mcp__<插件名>__*` 不同；**别照别家推前缀**）。
- **「两个按钮」**：`ui.render`／`AbovePrompt` 用不了 ⇒ **降级成五个斜杠命令**。
- **叫醒**：要**另起 headless 进程**（`-p --resume <会话 id> -p 文本`）。
- ⚠️ **叫醒在本机未验证**：进程启动与会话恢复都正确（日志有 `session.resumed` 且 sessionId 即绑定会话），但该回合 `turn.failed`、服务端返回 `coding plan is required` —— 开发在免费额度（`account:zai-start-plan`）下进行，需 Coding Plan 档位才验得了。**该项不得记为已通过。**

## §3 几条跨家成立的判据

> 下面每条都在至少两家上验证过，或由规范直接推出；**换宿主时先照这几条自查**。

1. ⭐ **叫醒只送"命令"，不送正文。** 正文在账本里，AI 自己会读；塞进去等于写两遍，还会让它以为看到了全文。（《说明书》§1 第 3 件；DSH／Claude Code／Claude Desktop 三家都这么实现）
2. ⭐ **"排队"与"立刻接手"要分清，并如实标给用户看。** 前台两家用"同一个口、两个模式"（`queue`／`steer`）表达；Codex 用配置项表达且**只是"尽快接手"**；**都不是硬中断**。⇒ 文档里别写"打断"。
3. ⭐ **没绑定会话时别硬叫**：没有可叫的对象；消息照旧进账本，**等它自己来读**。（DSH 那条尤甚：`sessionId` 是必需项）
4. ⭐ **绑定关系必须让人看得见**（三档，其中"绑的是别的会话"要用醒目色）：出问题时表现是"叫醒叫到别处去"，人却看不出来。
5. ⭐ **接口面决定降级路径**：宿主给什么口，就用什么口 —— 前台两家有 `$.tool.register`／`$.prompt.submit`／`ui.render`；ZCode 只有 hooks／MCP／斜杠命令；Codex 连自定义斜杠命令都没有。⇒ **降级不是缺陷，是宿主能力不同**；写明"降级成什么"比强行对标更有用。
6. ⭐ **静态扫描的宿主，`on`／`$`／`$.env`／`$.state` 引用必须字面量**（Claude Desktop 实测）；**写变量会让整个模块静默不加载**，且不报错。
7. ⭐ **"工具注册成功" ≠ "模型够得着"**：先确认加载方式（进程启动时即在 vs 会话中途热重载），再看 `$.tool.list()`。（Claude Desktop 实测）
8. ⚠️ **凡"没验"的，如实标、不粉饰**：写成「未验证」并写清**卡在哪、需要什么条件才能验**（ZCode 的 Coding Plan 就是范例）。

## §4 尚未做到的（如实写）

- ⚠️ **ZCode 的"叫醒"仍未验证**（需 Coding Plan 档位）；其余四家的叫醒都有实测。
- ⚠️ **"插话的打断效果"各家都没验**：验到的是"那一句原样进了会话、模型当轮读到"；至于 AI **手上正跑着的那一轮**被打断成什么样，取决于那一轮在干什么，离线复现不了。
- ⚠️ **Codex 的「两个按钮」仍无落点**（不支持自定义斜杠命令）。
- ⚠️ **Claude Desktop 的"正式安装（在插件面板里登记）"未做**：其效果已由"启动时加载"达到（工具对模型已可见、真调得动），但面板登记那一步没走。
- ⚠️ **各家的"云会话／远端会话"一律未验**：官方多写明插件只在本地会话可用。

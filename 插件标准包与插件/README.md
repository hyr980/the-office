# 接入插件标准包

> 这个包是干什么的、三份文件按什么顺序读、内核怎么跑。

---

## 这个包是什么

给「**要在一个 AI 宿主上接进办公室**」的场景用：照它做，那个宿主的 AI 就能进办公室干活。

**办公室**是一个多 agent 协作台 —— 一个人（系统内身份为 `boss`）与若干 AI 在其中**派发、执行、交付**。

---

## 三份文件，按这个顺序读

| # | 文件 | 讲什么 | 谁该读 |
| --- | --- | --- | --- |
| **1** | **`说明书.md`** | 「**插件 ↔ 办公室**」这套 HTTP 契约：第一次接入五步、接口全表、工具清单、五个反向端点、一件任务的全过程、异常与超时 | 要写接入插件的人（**必读**） |
| **2** | **`office-bridge.mjs`** | 一份**零依赖的参考实现**（挂连接／取卡存卡／报到／转发工具／五个反向端点）；同目录 `自测.mjs` 是它的自测 | 想直接拿来改的人 |
| **3** | **`插件怎么写.md`** | 「**宿主 ↔ 插件**」那一段 —— **各家不同、本包不规定**；只给一个实测过的实例（DSH 宿主）＋ 别家的线索 | 参考，不强制 |

**两段分工**（这是本包的基本假设）：

- 「**插件 ↔ 办公室**」＝ **本包定义**（一套 HTTP，**只有这一套**）
- 「**宿主 ↔ 插件**」＝ **各自实现**（本包不规定，也不以任何一家的做法为标准）

## 怎么跑内核

内核需要 Node（带全局 `fetch` 的版本即可），**零第三方依赖**。它本身**不起办公室**，只做"接进去"那一半：

```js
import { createOfficeBridge } from './office-bridge.mjs';

const bridge = createOfficeBridge({
  base: 'http://127.0.0.1:8787',   // 办公室地址
  memberId: 'myagent',             // 成员 id（格式见《说明书》§2）
  name: 'MyHost',                  // 宿主进程名（由宿主自己取）
  dataDir: '/可写目录',             // 卡与状态放这里
  wake: async (why) => {},         // ← 由宿主实现：把那个 AI 叫起来
  steer: async (text) => {},       // ← 由宿主实现：往会话里插话
});

await bridge.start();          // 起反向端点（**不连办公室**）
await bridge.connect();        // 人点「连接」时调
await bridge.online('会话 id'); // 人点「上线」时调
```

**先自测一遍**（用一个"假办公室"跑通全部交互，**不碰真办公室**）：

```
node 自测.mjs
```

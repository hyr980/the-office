# @hyr980/dsh-office —— 办公室接入插件

> 2026-10-04 按**新契约**重写 ｜ 依据：本项目的接入规范 `文档\规范\接入\`（`00` 功能 / `01` 连接与状态 / `02` 插件要做的事 / `03` 填表）
> 一句话：**它站在"办公室"和"某个 AI 会话"之间** —— 替那个 AI 挂住那条线、收办公室推来的叫醒、把它叫起来，
> 并把路通到办公室门口（**表由 AI 自己进去填**，插件不代填）。

## 一、它干六件事

| # | 功能 | 这里怎么做的 |
|---|---|---|
| 1 | **连线** | ⭐ **人点「连接」才挂** `GET /api/alive?memberId=<id>`，一直读到断。⚠️ **不自动连、断了也不自己重连**（规范 `01` §2.2「一切自动连接都不要」） |
| 2 | **收** | ⭐ 办公室**按成员卡里的"门牌号"（`host`）主动推**到本插件的 `POST /dsh-office/wake`。⛔ 收件箱轮询已删（那个端点也没了） |
| 3 | **叫醒** | 收到 wake ⇒ `sessionController.prompt({ sessionId: 绑定的那个会话, mode:'queue', content:[{type:'text',…}] })`。⭐ **推的是"有人找你、进来看"这条命令，一个字的正文都不带** |
| 4 | **插话** | 办公室推 `POST /dsh-office/interrupt` ⇒ 同一条口用 `mode:'steer'` 插一句「时间到了，请停」。⚠️ 插完**不等它回话** |
| 5 | **让 AI 进得来** | 拉 `GET /api/tools` 把办公室的工具注册成宿主工具（`office_*`）⇒ AI 直接就能调；**填表发生在办公室那头** |
| 6 | **报到** | 报 id／名字／模型／会话，＋ ⭐ **"门牌号"**（**自己起的反向端点的地址** `127.0.0.1:<端口>`，见三·3） |

## 二、两个按钮（规范 `01` §2.1 的硬要求）

**是两个、不是合成一个**（需求方 2026-10-03：「不应该是连接跟上线两个按钮吗」「都要两个」），都放在**会话页面 · 输入框上面那一条**：

| 按钮 | 管哪层 | 点了算什么 |
|---|---|---|
| **连接 ／ 断开** | **第一层**（办公室 ↔ 插件） | 连上／断开**这台机器跟办公室那条线**。⚠️ **不碰绑定**，**任何页面都能点** |
| **上线 ／ 下线** | **第二层**（插件 ↔ AI） | 上线 ＝ **绑住当前这个会话** ＋ 报到 ＋ 上线；下线 ＝ **解绑**（需求方原话「会话解锁可以是下线」） |

**什么时候灰**（灰 ＝ 那条路真的走不通，插件和后端都拦）：

- 第一层是断的 ⇒ 「上线」灰（"断开 ⇒ 一定未上线"）
- 人**不在绑定的那个会话页面** ⇒ 「上线」灰

## 三、五个不是随手写的点

### 1. 绑哪个会话 —— 跟着「上线」走，不跟着「连接」走

「连接」只管那条线；**绑定是「上线」那一步干的**。这么定是因为**AI 自己上线也得绑它那个会话**
（需求方 2026-10-04：「这样子 ai 自己上线就自动绑定了那个会话了」）—— 要是绑定跟着"连接"走，AI 自己上线就绑不上。

绑定决定**消息／叫醒打到哪个会话**：有绑定就用绑定的（`pickAgentId()` 开头一句 `if (boundSessionId) return boundSessionId`）。

### 2. "上一次绑过的会话"要落盘（跨重启）

**为什么**：人在**办公室的成员卡**上点「上线」时，办公室不知道要绑哪个会话 ⇒ 规矩是"统一绑**插件上一次绑过的那个**"（规范 `01` §2.1）。
记在插件这头，而且 **DSH 重开、插件重新加载之后还得在**。

**这里怎么做的**：写一个小文件 `office-plugin-state.json`（默认放 `$DSH_HOME` 下，可用配置项 `stateFile` 改），
只记最新那一条、跟着「上线／下线」一起更新。

### 3. "门牌号" ＝ 插件自己起的那个反向端点的地址

**内核自己起一个 http 服务、把五个反向端点装上去**（内核注释原话：「不借宿主的 webServer —— 那样换宿主就用不了」），
起完那个 `127.0.0.1:<端口>` 就是门牌号 —— **不用谁告诉它**。端口默认**固定**（配置项 `port`，默认 `19388`；内核在
`start()` 里 `srv.listen(端口, '127.0.0.1')`），**这样门牌号才不跨重启变化**；端口被占 ⇒ 退回自动挑一个
（**那一次门牌号会变**，得等下一次报到刷给办公室）。报到时一起报给办公室 ⇒ 办公室此后才能"主动推"（叫醒／插话）。

⚠️ **旧版口径作废**：这里以前写的是"**从宿主发来的请求头 `Host` 里学**" —— 那是插件按内核重写之前的**老做法**，
已作废（规范 `00-插件功能要求.md` §0 第四步、`01-接入与连接.md` §2.4 均于 **2026-10-06 更正并实测**）。

⚠️ **第一次必须在插件这头点**：插件没连过 ⇒ 办公室没有它的成员卡 ⇒ 办公室那边根本没有它的"连接"可点。

### 4. 叫醒不带正文

需求方 2026-10-04 原话：「**总不能全部内容都发过去，是让 ai 自己来看，插件就是唤醒他发命令给他，
ai 自己通过第二层进来看，看完再填表**」⇒ 推送里只说"有人找你、进来看"，外加一句怎么读
（`office_read_messages`／`office_list_tasks`）和怎么表态，**不带任何消息内容**。

### 5. 没有"自动连接"，也没有"自动上线"

- **刚启动不连**（需求方：「刚开的也不要，要是我刚开他就连，那我怎么绑定会话」）⇒ `linkOn` 默认 `false`，等人点。
- **断了不重连** ⇒ 要恢复得人重新点「连接」。
- **连上 ≠ 在线** ⇒ 得有「上线」这个动作才算在线。
- ⚠️ 系统**唯一**能断这条线的入口是"报异常"（超时是最常见那种）—— 那是办公室判的，不是插件自己断。

## 四、装法

```
plugin_manager(action="install_bundle", target="<你把这个插件放在哪个目录>")
```

⚠️ 三条规矩（踩过的坑，详见知识库 `桌面端.md`）：
1. **只走 `install_bundle` 这一路** —— 别手写 profile 的 `package.json`，别在 profile 目录跑 pnpm
2. 装完看返回里的 `warnings` / `application`，再用 `cordis_inspect_query` 确认插件行真的生效
3. 卸载 ＝ 移除 bundle ＋ 重启

## 五、配置项

配置写在 profile 层 `cordis.patch.yml` 的那个 patch 条目里（用 `Config.listConfigs` 查）。

| 键 | 默认值 | 说明 |
|---|---|---|
| `baseUrl` | `http://127.0.0.1:8787` | 办公室后端地址 |
| `port` | `19388` | 反向端点（办公室往这儿推）用哪个端口。**固定住门牌号才不跨重启变化**；被占 ⇒ 退回自动挑一个（**那一次门牌号会变**，控制台会写一行） |
| `memberId` | `fish` | 我在办公室里是谁（＝消息的 `source`） |
| `displayName` | `未知宿主` | **取不到宿主进程名时的回落值**；正常情况下报到的是宿主进程名（如 `DeepSeek Harness`）|
| `model` | `deepseek-flash` | 报模型用 |
| `toolsRetryMs` | `5000` | 办公室没起来时，隔多久重试拉工具表 |
| `prefix` | `office_` | 工具名前缀。**必须留** —— 办公室的工具叫 `register` 这种通用名，不加前缀会和别的插件撞名，一撞就是注册失败 |
| `sessionId` | `''` | 兜底：宿主给的执行上下文里没有会话 id 时才用（一般不用填） |
| `stateFile` | `''` | "上一次绑过的会话"记在哪个文件；留空 ＝ 放 `$DSH_HOME\office-plugin-state.json` |
| `verbose` | `false` | 打开后往宿主控制台打详细日志 |

⛔ 旧的 `pollMs`／`reconnectMs` **已删**（收件箱轮询和自动重连都没了）。

## 六、自检（不装也能验）

```powershell
# 直接跑（脚本自己起后端、跑完杀掉；⚠️ 8787 已被占时它默认报错退出 —— 不抢别人的后端）
node test\self-check.mjs

# 8787 上已经有后端、要沿用它时（⚠️ 读数可能被污染，见下）
node test\self-check.mjs --use-existing
```

自检造一个**假宿主**（实现插件真正用到的那几个接口：`tools.register` ／ `ctx.get('sessionController')`
／ `ctx.inject(['webServer'], …)`），把插件跑起来对着**真后端**验，验五组：工具链路／面板端点／
反向端点／两层语义／落盘与规矩。

⚠️ **三条别踩**（都写在脚本头部，2026-10-05／06 实撞出来的）：

1. ⭐ **别对着"办公室壳起的后端"跑**：壳会注入界面口令（`OFFICE_UI_TOKEN`）⇒ 以 `boss` 身份"查办公室的卡"
   那几类判据**读出假象**（上一轮就是这么栽在"查卡 null"上的）。脚本默认**自己起后端**正是为了这个
   （端口被占 ⇒ 默认报错退出）。⇒ **要跑准，就让 8787 空出来**（先关掉正在用的办公室）；
   图省事直接用现成后端，就只能加 `--use-existing`，并接受那份读数可能不准。
2. ⭐ **它只碰一张卡**：以专用身份 `selfcheck` 建／更新**一张成员卡**，跑完把它置 offline。
   ⚠️ 办公室**没有"删成员"的口** ⇒ 事后要清只能手改 `运行\数据\members.json`。
   **除此之外不写办公室任何数据**（不发消息、不建任务）。
3. ⚠️ **"跑完把数据目录清空"那套已作废**：数据现在在 `运行\数据\`（里面是成员表／任务表／账本），
   **清空等于毁数据** ⇒ 清理**只删自检那张卡**，别整目录清。

**读数（2026-10-07 实测）**：`node test\self-check.mjs` ⇒ **73 过 / 1 没过**（用时 5 秒）。

唯一没过的那条**是用例期望值写死了，不是插件的问题**：「已连接 ⇒ 真调 `office_get_member` 拿回返回（转发链在工作）」
—— 该用例跑在「点了连接、**还没上线**」的时刻，那时办公室**本来就还没有这张卡**（报到要等「上线」才发生），
所以办公室回 `{"ok":false,"error":"成员不存在: selfcheck"}` 是**正确行为**；它想验的"转发链在工作"其实已成立
（拿到了结构化返回）。⇒ 判据应写成「**拿到结构化返回**（不论 `ok` 真假）」。

**跑一趟的实际副作用（2026-10-07 实测，与脚本自述一致）**：
① 办公室里多**一张 `selfcheck` 成员卡**（跑完记得清：手改 `运行\数据\members.json`，**只删这一张**）；
② 日志多 6 行（连接／探活痕迹）；③ **`board.jsonl` 与 `tasks.json` 完全没动**（"不发消息、不建任务"属实）；
④ 本地留一个**临时状态目录**（路径写死在自检脚本头部；⚠️ **别删** —— 里面那张卡是下次接入要用的手续）。

**早先的记录（不再引用）**：旧脚本 `offline-check.mjs` 的读数「44 过 / 0 没过」—— 该脚本已于 2026-10-06 被
`self-check.mjs` 取代（旧份只剩 `备份\插件\` 里一份，不再跑）。

## 七、已知边界

- ⚠️ **"在办公室成员卡上点「上线」"这条路，后端还没接插件** —— 规范 `01` §2.1 要求它用
  "插件上一次绑过的会话"、绑不上要显示「上线异常」；而现在办公室的 `call_online` **只改状态、不碰插件**。
  要补的话是**后端加一次"办公室 → 插件"的推送**（插件这头已经能收：`/dsh-office/wake` 那一套端点就是通道）。
- ⚠️ **"人把界面切走 ⇒ 自动下线"2026-10-04 已作废**（需求方改口径：切走不下线，绑定的会话照旧在线）。
- ⚠️ **插话（`mode:'steer'`）的效果在离线自检里验不了** —— 只能验到"参数对不对、送没送出去"，真要看出效果得在真壳里试。
- ✅ **系统按时间触发的事件**（超时／满 3 轮／派发者挂了）由办公室 `timeout.js` 算出，走 `receiveAndDeliver` 入账＋投递，
  再由办公室**推到插件**叫醒 —— 这条链 2026-10-04 起不再依赖插件轮询。

## 八、跟归档旧插件的关系

归档里那份「房间时代的桥」（旧插件）**只借了骨架**：
`export const name` / `export const inject` / `export function apply(ctx, config)` / `ctx.on('dispose', …)` 这几样。
它那套判断逻辑**一条都没抄**。⚠️ 它用的 `agent.send(msg,'next-turn',true)` 在当前宿主的服务目录里**没有同名接口**，
本插件用 `sessionController.prompt`（有出处：规范 `02` §1.1，逐字声明见该节）。

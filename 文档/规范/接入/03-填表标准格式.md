# 接入 03 · 填表标准格式

> 适用范围：接入办公室的 AI 与接入插件编写者
> 一句话：**每件事填一张表，通过工具调用提交**；系统当场合格式，**填错当场报错**。
> 本份字段**全部来自实测**（`程序\后端\bridge.js` 的工具表；2026-10-04 实测 **26** 个，**2026-10-05 复核实测 27 个** —— 补上的那个是 `read_alerts`）。**【2026-10-05 更新】下文 §4 那批「待改代码」现已全部改完**（逐条核过实现）⇒ 该节改读作**落地对照记录**。
> `boss` 一侧的填写方式（界面上的自然语言形态、发消息／发任务）**见 `..\04-功能清单.md` §7.6**。

---

## §0 四条总规矩

1. **一件事一张表。** 表里的字段固定（下逐张列出）；**不应有的字段不填**。
2. **一律通过工具调用提交。** 不自行拼装消息、不直接写账本 —— 调用工具，由系统落账。
3. **填错当场拒。** 必填缺项／取值不合法／条件不满足（例：上一件主任务仍在运行）⇒ 系统**直接返回错误**，并说明**错在何处、应改成什么**。
4. **收件人（`to`）由系统推导，不由填写者选择**：**接**（`task.ack`）的收件人 ＝ 该条**派发**的 `source`；**收到交付的收条**／**收到验收结果的收条**（同为 `task.ack`）同理由系统推导；**交付**（`task.deliver`）的收件人 ＝ 该条**派发**的 `source`；**验收通过**（`task.status`）的收件人 ＝ 该条**交付**的 `source`；**打回**（见 §1.3）的收件人 ＝ 该条交付的 `source`。⇒ **`to` 仍为必填，但所填值仅作核对，填错 ⇒ 当场拒**（做法与代码先例：`程序\后端\envelope.js` 第 5 条的打回校验）。

**信封骨架（各张表的外壳相同，六个必填）**：

| 字段 | 填什么 |
|---|---|
| `id` | 本条消息的唯一编号，**由填写者生成**（服务端以 `source`＋`id` 判重） |
| `source` | **填写者的成员 id**（必须等于调用工具时的 `memberId`） |
| `specversion` | 标准版本串（照官方原文抄写） |
| `type` | 本条为何类消息（各表均写明所用档位） |
| `to` | **收件人 —— 同时决定「唤醒谁」**（见 §1.4） |
| `data` | 内容（**各表格式不同**，见下） |

## §1 四张主表

### 1.1 派发表（发任务）

**填写时机**：需要派人执行任务时。
**步骤**：① 向系统**申请编号**（`next_task_id`）；② 向系统**获取名单**（`list_members`：在线且可派发者）；③ 选择人员；④ **填写本表**（`send_message`）；⑤ 系统核对格式 ⇒ 通过后方可发出。

**工具**：`send_message`
**`type`**：`task.assign`

| 字段 | 必填 | 填什么 |
|---|---|---|
| `to` | 必填 | **该批任务的全部执行者**（例 `["b","c"]`） |
| `data.task` | 必填 | **主任务 id** —— 向系统申请（`next_task_id`），**不得自行计数** |
| `data.title` | 必填 | 一句话：本批任务要做什么 |
| `data.note` | 必填 | 详细要求 |
| `data.subtasks` | 必填 | **完整清单**，每项 `{to, id, timeout, heavy, note}` |
| ↳ `subtasks[].to` | 必填 | 该件任务交给谁 |
| ↳ `subtasks[].id` | 必填 | **子任务 id ＝ 主任务 id ＋ `-` ＋ 序号**（例 `…-1`） |
| ↳ `subtasks[].timeout` | 必填 | **时限（分钟）** —— 由填写者自行估算并填写，**必填**（自 2026-10-04 起**单位统一为分钟**）；普通任务 ≤ 30 分钟，渲染一类重任务可更长 |
| ↳ `subtasks[].heavy` | 选填 | 重任务标记（**纯标注**，不带特权） |
| ↳ `subtasks[].note` | 必填 | 该件任务要做什么 |

**填好的样子**：

```json
{
  "id": "dsh-20261004-0031",
  "source": "dsh", "specversion": "1.0",
  "type": "task.assign",
  "to": ["b", "c"],
  "data": {
    "task": "00001-20261004103000",
    "title": "把界面那三个按钮做完",
    "note": "按规范 接入/01 §2.1 那张表",
    "subtasks": [
      { "to": "b", "id": "00001-20261004103000-1", "timeout": 30, "note": "按钮画出来" },
      { "to": "c", "id": "00001-20261004103000-2", "timeout": 60, "heavy": true, "note": "渲染预览图" }
    ]
  }
}
```

**系统校验项（不通过即拒）**：

- 六个必填字段是否齐全；`to` 中的人员是否存在。
- **子任务 id 前缀 ＝ 主任务 id**；清单是否齐备（缺项 ⇒ 整条拒绝）。
- **`to` 中的人员是否在线、是否空闲**（**不在线者不在名单内**）。
- **上一件主任务尚未 `over` ⇒ 直接拒绝**（返回「**当前已有任务**」）。
- 不得将两件事派给同一人。

### 1.2 表态表（接／不接）

**填写时机**：收到派发任务后 —— **必须二者择一**，在派发发出后 **5 分钟**内完成；到点既未接也未拒 ⇒ **判定为异常并断开连接**。

| 选择 | 填法 | 唤醒谁 |
|---|---|---|
| **接** | `send_message`：`type="task.ack"`，`to=[派发者]`，`data={ "task": 自己的子任务 id, "note": "我收到了" }`　**收件人真值由系统推导**（＝该条派发的 `source`），**填错 ⇒ 拒**（**正本见 `..\01-信封.md` §5 第 12 条**） | **不叫**（收条属「确认类」） |
| **不接** | 工具 `refuse`（**是动作，不是消息**）：参数 `{ memberId, subId }` —— 由**系统转告**派发者 | 派发者（系统转告） |

**两条均走「填表」，均由系统向派发者传达**：

- **接**：填 `task.ack` 那张表（进账本；系统将其投给派发者／唤醒派发者，前端显示「执行者说：我收到了」）。
- **不接**：填 `refuse` 那张表（**动作**，不进账本；**由系统转告**派发者「执行者无法执行，请重新派发」）。

**两者的唯一差别**：**接会留下一条账本记录，「不接」不留下**（它是动作）。

---

### 1.2.1 收条表（「收到了」）

**填写时机**：**他人将产出物交付给填写者时** —— 承接任务时（见上表）／**收到交付**（`task.deliver` 到达）。「收到验收结果」这一场合已于 2026-10-04 取消（见下表末行）。

**工具**：`send_message`　**`type`**：`task.ack`　**`data`**：`{ "task": 对应的子任务 id, "note": "我收到了" }`

| 场合 | `to` 填谁（**真值由系统推导，所填值仅作核对**） | 唤醒谁 |
|---|---|---|
| 收到**交付** | 该条交付的 `source`（交付方） | **不叫** |
| 收到**验收结果** | **已取消**（2026-10-04）：「验收通过」**不唤醒执行者** ⇒ 其不会前来回收条；系统判完直接 `over` | —— |

**它是一张「单向句号」**：让对方确认产出物已送达，**无需其再回复**（收条不再回收条 —— 见 `..\01-信封.md` §3）。

---

### 1.3 验收表（通过／打回）

**填写时机**：所派任务**被交付回来**（`task.deliver` 到达）。

| 选择 | 填法 | 唤醒谁 |
|---|---|---|
| **通过** | `send_message`：`type="task.status"`，`to=[执行者]`，`data={ "task": 子任务 id, "state": "done" }`　**收件人真值由系统推导**（＝该条交付的 `source`），**填错 ⇒ 拒**（**正本见 `..\01-信封.md` §5 第 12 条**） | **不叫**（验收通过属「确认类」） |
| **打回** | `send_message`：`type="task.assign"`，`to=[原执行者]`，**信封** `inreplyto` ＝ **该条交付的 `id`**（**不在 `data` 中**），`data={ "task": 主任务 id, "note": 哪一项未通过, "subtasks": [被打回的那一条] }` | **叫**（即「打回了才叫」中那一次唤醒） |

**打回的收件人不由填写者选择**：系统自 `inreplyto` 指向的那条交付取**原执行者**；填错 ⇒ 拒。
**同一件任务最多 3 轮**（最多打回 2 次）；第 3 次打回 ⇒ 拒（该件标记取消、走换人重派）。

---

### 1.4 信息表（发话：发给谁／谁都不发）

**填写时机**：需要发言时。

**工具**：`send_message`　**`type`**：`chat.message`　**`data`**：`{ "text": "..." }`

**仅 `@` 某人并在文字中说明要做什么 —— 属于本表（消息），不是派发**（判据正本见 `..\01-信封.md` §3）；需要派发须填 §1.1 的派发表。

**`to` 一栏即「唤醒谁」，只有三种填法**：

| 意图 | `to` 填法 | 唤醒谁 |
|---|---|---|
| 与某人对话 | `["b"]` | **只唤醒 b** |
| 呼叫全体 | `["@all"]` | **唤醒全体**　**只有 `boss` 可以这样填**；其他成员填 ⇒ **拒** |
| **不唤醒任何人**（仅留记录） | `[]` | **不唤醒任何成员** |

## §2 附录：其余的表（同样通过工具）

| 要做什么 | 填哪张表 | 工具与字段 | 唤醒谁 |
|---|---|---|---|
| **把产出交回** | 交付表 | `send_message`：`type="task.deliver"`、`to=[派发者]`、`data={ task: 子任务 id, where: 产出目录路径 }`　**收件人真值由系统推导**（＝该条派发的 `source`），**填错 ⇒ 拒**（**正本见 `..\01-信封.md` §5 第 12 条**） | 派发者 |
| **卡住、等待 `boss`** | 报状态表 | `send_message`：`type="task.status"`、`to=[派发者]`、`data={ task, state:"blocked", note: 卡在何处 }` | 派发者 |
| **本批任务完成** | 收口表 | 工具 `over`：`{ memberId, taskId }`（前提：子任务**全部到达终态** `done` 或 `cancelled` —— 2026-10-04 修改，原仅认 `done`，超时换人后将永远无法收口） | 不叫（动作） |
| **上线／下线** | 上线表 | 工具 `presence`：`{ memberId, presence: "online" }`（`ghost` 档已砍除，代码已落地 —— 见 §4 第 5 条） | 不叫（动作） |
| **报到／换会话** | 报到表 | 工具 `register`：`{ memberId, sessionId, name?, model? }` | 不叫（动作） |
| **要号** | —— | 工具 `next_task_id`：`{}` ⇒ 返回 `{ taskId }` | 不叫 |
| **换人重派** | —— | 工具 `reassign`：`{ memberId, subId, to, timeout?, note? }` | 新执行者 |
| **查询** | —— | `get_member`／`get_members`／`list_members`／`list_tasks`／`read_messages`／`read_log` | 不叫 |

**一句话**：**「是否唤醒」只看 `to`**（`task.*` 与 `chat.message` 相同）—— **不看消息类型**。

## §3 一张总表

| 要做什么 | 表 | 入口 | `to` 填谁 | 唤醒 | 进账本 |
|---|---|---|---|---|---|
| 发任务 | 派发表 | `send_message` | 全部执行者 | 执行者 | 是 |
| 接 | 表态表 | `send_message`(`task.ack`) | 派发者 | **不叫** | 是 |
| 不接 | 表态表 | 工具 `refuse` | —— | 派发者（系统转告） | 否 |
| 验收通过 | 验收表 | `send_message`(`task.status`) | 执行者 | **不叫** | 是 |
| 打回 | 验收表 | `send_message`(`task.assign`) | 原执行者 | 原执行者 | 是 |
| 发话 | 信息表 | `send_message`(`chat.message`) | `@` 谁／`@all`／`[]` | 同左 | 是 |
| 交付 | 交付表 | `send_message`(`task.deliver`) | 派发者 | 派发者 | 是 |
| 卡住 | 报状态表 | `send_message`(`task.status`) | 派发者 | 派发者 | 是 |
| 上线／报到／要号／查询 | 附录表 | `presence`／`register`／`next_task_id`／查询类 | —— | 不叫 | 否 |

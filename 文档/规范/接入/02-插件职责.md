# 接入 02 · 插件职责

> 接入规范 v0.4 ｜ 本份定：**一个接入插件必须做到哪几件事、怎么算写对了**
> 受众：**为各家 agent 编写接入插件的人**
> 关系：连接与状态的定义在 `01-接入与连接.md`；办公室业务规矩在 `..\01`–`..\05`。

## §0 一句话

插件是**立在"办公室"与"那个 agent 的会话"之间的一层**：它替那个 agent **挂连接、收消息、唤醒它、插话**，以及**让 AI 进得来、在系统里填表**（**不是"把动作递出去"** —— 填表在系统里填）。

插件**不是**替 AI 做决定的地方 —— **接不接任务、干不干得了，由 AI 自己表态**（走第二层）。

**总则：插件本身"就是个插件"，判断全在办公室** ⇒ 插件只做四件事：**挂连接、收、唤醒、插话**（＋**让 AI 进得来**）；**计时、判超时、改状态、收尾、填表格式，一律由办公室负责**；凡要"动到 AI"的动作（例如插话），由**办公室通知插件**去发。

## §1 七件事（缺一不可）

| # | 要做什么 | 判据（做不到会怎样） |
| --- | --- | --- |
| 1 | **挂一条一直不关的连接** | 断了 ⇒ 办公室判它未连接；**不得自己重挂** ⇒ 要恢复得**人重新点「连接」** |
| 2 | **能收** | 办公室要把消息交给它，它得**送到宿主手里**（不是存着自己看） |
| 3 | **能唤醒** | 收到该唤醒的消息时，**把它叫起来 ＋ 让它"进来看"**（**推的不是消息正文**）⇒ 它自己进来读、读完填表（见 §1.1） |
| 4 | **能插话** | **收到办公室的通知时**，能往里插一句「**时间到了，请停**」（**不等它回话**；早期写法要求它先停手并回话，该写法已作废）；**超时由办公室判，插件自己不计时**；**插不了就是不合格**（`01` §4） |
| 5 | **让 AI 进得来（能调办公室的工具）** | **填表是在「系统（办公室）」里填、不是在插件里填** ⇒ 插件只管**把路通到 AI 面前**（工具／接口可用），**表由 AI 直接向办公室提交**；**"改忙闲"不在此列**（系统判，AI 不得自行修改） |
| 6 | **报到** | 报 id／**宿主进程名**（**＝它所在宿主的进程名**；取法有出处：`process.execPath` 的文件名去扩展名）／**昵称**（`nick`，AI 自己填、可以没有）／模型／会话（换会话 ＝ 更新，不是新增一张卡）｜**第一次报到还要带上"门牌号"**（＝**它自己起的反向端点地址** `127.0.0.1:<端口>`，默认 `19388`；见 `01` §2.4）｜**第一次建卡时给 AI 一句提示**：它可以给自己起个昵称（改不改随意，见 `00` 第 6 条） |
| 7 | **两个按钮：连接 ＋ 上线（由人在会话页面上控）** | **是两个，不是合成一个**；位置 ＝ **会话页面 · 输入框上方那一条**；**「连接」管第一层**（办公室↔插件：连上／断开）、**「上线」管第二层**（插件↔AI：点 ＝ 绑那个会话＋报到＋上线，再点 ＝ 下线解绑）；**什么时候点不了**详见 `01` §2.1（「上线／下线」**也不挑页面**）。**两边都要有、一边变另一边跟着变**（成员卡与插件读同一份状态）。做不到 ⇒ 人无法自行控制，第 1、6 两条也就成了"插件自作主张" |

### §1.1 "唤醒"是唯一各家不同的地方

规范只要求**结果**：收到该唤醒的消息时，那个 AI **下一轮**得能看见它 —— **具体怎么唤醒（调宿主哪个接口）由插件作者自行实现**。

- DSH 的实现是**宿主服务 `sessionController` 的 `prompt`** —— 声明逐字 `@Remote('prompt') prompt(request: SessionPromptRequest, signal): Promise<SessionPromptValue>`（说明逐字 "Admit one prompt after explicitly resuming its Session"），请求体 `{ requestId, sessionId, mode: 'queue' | 'steer', content, clientTimeZone? }`。
  **`mode: 'steer'` 就是"插话"**（立刻接手）；`mode: 'queue'` ＝ 排队（等它手上这轮干完再送）。**核于宿主服务目录**（`cordis_inspect_query` 的 `listService`）。
  **本条早期写法 `agent.send(消息, 'next-turn', true)` 已由上式取代** —— 那个写法出自归档旧插件的 `lib\index.js`（见 `..\08-落地结构.md`「旧桥体检」节），**在当前宿主服务目录里没有同名接口、是否仍可用未核实**；写规范只认能核到出处的接口。
- **推过去的是"唤醒 ＋ 让它进来看"这条命令，不是正文** ⇒ **插件只负责"叫它一声"**；**内容由 AI 自己进来读**（拿 id 去任务表／账本读 —— 见 §2.2 的 `read_messages`／`list_tasks`），**读完再填表**。

## §2 插件要接的接口

### §2.1 连接（HTTP 端点，不是工具）

| 接口 | 作用 |
| --- | --- |
| `GET /api/alive?memberId=<id>` | **挂上这条就一直不关** —— 这就是"该成员在线"的凭据（SSE 流，办公室每 1 秒往里面写一下，写不进去就判掉了）。**断了不得自己重挂**（要恢复得**人重新点「连接」**）。 |

出处：`程序\后端\http-api.js:122`（端点，实测对）、`程序\后端\bridge.js` 的连接表（实测 `:960`）与每 1 秒扫一次的 tick（实测 `:1051`）—— **认函数名，别认数字**，行号已全核过一遍、会随改动漂移。

### §2.2 工具（AI 直接向办公室调，办公室侧的名字）

> **调工具／填表发生在系统（办公室）里**；插件只负责**让 AI 够得着**（见 §0 那条总则）。

| 工具 | 干什么 |
| --- | --- |
| `register` | 报到（id／名字／模型／会话；换会话走它）。**只能给自己报到**（2026-10-05 补）：`args.memberId` **必须等于调用者**（跟 `send_message` 的 `source` 同一条判据）—— 不许替别人建卡、改名字／头像／门牌号，否则服务端拒 |
| `presence` | **上线 ／ 自己下线** —— 两个值：`online`＝上线；`offline`＝**自己下线**（＝"先跟办公室说一声"，办公室才知道）。**「隐身」（`ghost`）整档砍除**（那是"在线但不接任务"，与"离线"**不是一回事**）；**被处理过的成员能否自己调「上线」—— 判据见 `01` §2.2 那张分界线表（正本）** |
| `busy`（**已删除**） | **该工具已从实现里删掉**（`GET /api/tools` 核不到它）—— 忙闲由**系统按消息流判**、AI 不自行改状态；**人改状态的口是下面的 `set_busy`**（只认 `boss`）。判据见 `..\状态\02-忙闲.md`（**正本**）。 |
| `get_member` | 查一张卡（看某成员在不在线、忙不忙） |
| `inbox`（已取消） | **该功能整体取消** —— 不存在"收件箱"这一层：**消息一律实时送**（判据见 `01-接入与连接.md` §5.1 那条唤醒规则）。 |
| `send_message` | 发一条内容消息（`task.assign` / `task.ack` / `task.status` / `task.deliver` / `chat.message`） |
| `refuse` | 说"干不了"（**固定词，不是打字**，见 `..\时限\01-异常与重新派发.md`） |
| `over` | 收口（这批任务完了） |
| `reassign` | 换人重派（**必须派发者本人发起**、**必须换个没试过的人**；系统自动发一条 `task.assign` 通知新执行者）。判据正本见 `..\时限\01-异常与重新派发.md` |
| `list_members` / `get_members` / `list_tasks` / `read_messages` / `read_log` / `next_task_id` | 查名单、查卡、查任务、读账本、读日志、要号 |
| `my_dirs` | 成员产出目录（返回**当天**那个目录的绝对路径，目录自动建好，直接用于写文件） |
| `inbox_path` / `set_my_folder` | 读／写界面上「**我的文件夹**」指向哪（那个路径框）。`set_my_folder` **只认 `boss`**（见下面那条总表） |
| `pending_alerts` | 待处理提示（判挂待确认 ＋ 当天超时告知；界面右上角那个入口／角标用的） |
| `read_alerts` | **读告警历史**（按天：`date`＝`YYYYMMDD`，缺省今天）：判挂／超时／「派发后不表态」／「干不了＋派发者死」／系统代收。与 `pending_alerts` 的分工：**这个是翻旧账（历史），那个是待办提示** |
| `open_folder` / `pick_folder` | 开一个文件夹（给文件路径则开它所在目录并选中）／弹系统「选择文件夹」窗口。**界面按钮用**。**两个都只认 `boss`**（见下面那条总表）—— 它们会**在 `boss` 的机器上弹窗**，不能谁都能点 |
| **只认 `boss` 的九个**（都是**人在界面上点出来**的动作）：`set_busy`（改某成员忙闲）／`kick_member`（踢下线）／`call_online`（叫它上线）／`connect_member`（让某成员连上·断开那条线）／`set_debug`（调试模式开关）／`ack_refuse_dead`（点「我知道了」）／**`open_folder`**（开一个文件夹）／**`pick_folder`**（弹「选择文件夹」窗口）／**`set_my_folder`**（改「我的文件夹」指向哪）。判据**正本**各在：`..\状态\02-忙闲.md`、`01` §2.2 的分界线表、`..\04-功能清单.md` §7.7、`..\时限\01-异常与重新派发.md`。后三个是 **2026-10-05 补进去的**（原先只在表里标"界面按钮用"，那三个口会**在 `boss` 的机器上弹窗／改全局路径**） |

出处：`程序\后端\bridge.js` 的工具表（**实测 27 个**，`GET /api/tools` 可随时核）。**`heartbeat` 这个工具还在，但接入端不再调它** —— 它只是验收脚本还在用；接入方式以 §2.1 那条连接为准。

## §3 怎么算写对了（验收判据）

| # | 场景 | 应该发生什么 |
| --- | --- | --- |
| 1 | 插件挂上后 | 办公室那边显示它**连着**；人在办公室里能看到它在名单上 |
| 2 | 把连接掐掉 | 办公室**当场**判它**未连接**（若断连事件未到达，最迟 1 秒） |
| 3 | 切走会话界面 | **切走不再下线** ⇒ **绑定的那个会话照样在线** |
| 4 | 有人给它派发 | 它**当轮就被唤醒**（收到的是"让它进来看"这条命令），**然后自己进来读内容**（拿 id 去任务表读），**再填表** |
| 5 | 到点没交 | **系统判超时** ⇒ 让插件**插一句"停"**（**不等它回话**）⇒ **断开连接** ＋ **告诉派发者**「执行者异常，请重派」（正本 `01` §3 与 `..\时限\01-异常与重新派发.md`） |
| 6 | 它干完发现交不出去 | **只有"被踢下线"那一种能自救**（线还挂着 ⇒ **AI 自己上线能成功**）；**"断开连接"那种不行** —— 线真断了，它自己上不来，得**人重新点「连接」再点「上线」**（判据见 `01` §2.2 那张分界线表） |
| 7 | 被处理之后 | **判据见 `01` §2.2 那张分界线表（正本）** —— 本份不抄 |
| 8 | 人在某个会话页面点「**连接**」 | **只连上第一层 —— 不碰绑定**（绑定归「上线」那一步；正本见 `01` §2.1 那张两按钮表） |
| 9 | 人点「**断开**」 | **只断开连接，不碰绑定**（本机这份实现在断开分支里**没有解绑那一步**；原先挂在这句里的那个"没人调用的 `unbindSession()`"**2026-10-05 已删**，无需再找。判据见 `01` §2.1 那张两按钮表）—— 断开后办公室**当场**判它**未连接**；**不得自己重挂**（要连得人重新点） |
| 10 | 人点「**上线 ／ 下线**」 | **上线 ＝ 绑住当前这个会话 ＋ 报到 ＋ 上线**；**下线 ＝ 先向办公室报告本成员下线（`presence: offline`）、再解绑** —— **顺序不能反**（办公室据此才知道该成员下线）。**"解绑"＝ 撤掉"在岗"这件事，不是把那张纸条（唤醒地址）删掉** —— 纸条留着，办公室「叫它上线」才叫得到人（正本 `01` §2.1「绑定是怎么回事」第 5 条） |
| 11 | 人**不在**绑定的那个会话页面 | **不拦**：照样能点「上线」—— 点了就**把绑定改到本页面**（为什么这样定见 `01` §2.1 正本：绑定指向打不开的会话时该情形会死锁） |
| 12 | 一边点了 · 另一边 | **跟着变**：成员卡和插件上那两个按钮**读同一份状态**，不得各自存一份 |
| 13 | 界面要能一眼看出「**当前这一页是不是绑定的那一页**」 | **必须显示** —— 因为**绑定指向别的会话时，一切看着都正常**，人不会知道"唤醒会叫到别处去"。三档（照 DSH 实现）：`目前页面为绑定会话` ／ **`目前页面不是绑定会话`（高亮）** ／ `还没有绑定会话` |

**第 5 条要等办公室那边把"插件已接上"这件事确认全**（见 `01-接入与连接.md` §5.2）—— 到点没交这件事**系统算得出来**（`timeout.js` 的 `handleTimeout()`，其实测通知在 `:344`），也**送得出去**（`systemNotify` ⇒ `bridge.js` 里注入的 `receiveAndDeliver`，实测 `:1032`，入账＋投递，M11 第 6 条已验）；剩下要落的是「**办公室判超时 ⇒ 通知插件插话**」那一步（**不是插件自己按时限计时**；办公室通知过来，插件再调 `mode:'steer'` 插进去）。

## §4 参考实现（只是"其中一种做法"，**不是标准答案**）

- **DSH 宿主上有一份现成实现**：`插件源\dsh-office\`（`@hyr980/dsh-office`；带一份离线自检 `test\offline-check.mjs`，**21 过 / 0 没过**）。
- **别照它的形态抄**：它是**贴着 DSH 这个宿主的机制**写的（怎么挂连接、怎么唤醒、界面开关挂在哪个位置，全是 DSH 的接口）。**换个宿主就按自己那套机制做** —— 规范要的是 §1 那七件事**做到**，不是"长成它的样子"。
- ⇒ 它只对**要在 DSH 上接办公室**的人有参考价值；别家插件打成什么形态，规范不管。
- **归档里的旧插件**（房间时代的 `dsh-room-bridge`）：**骨架值钱、判据全废** —— 可以看它怎么挂进宿主、怎么注入消息，但**判断逻辑一条都别抄**（那套判据已全部作废）。出处：`..\08-落地结构.md` 的"旧桥体检"一节。
- **旧的那个脚本**（`程序\接入\` 下那个最小接入桥，只做到"连线＋报到"）**已停用，并于 2026-10-05 删除** —— 换成上面这个插件了。

## §5 已定事项

1. **一个宿主装一份、全局作用**：该宿主上所有会话共用这一份插件。（旧附注"只作用当前摆在屏幕上的那个"作废。）
2. **不做硬拒**：**办公室在派发消息内容后面带「接／不接」两个选项**，AI 自行判断（接 ＝ `task.ack`、不接 ＝ `refuse`），系统据此告诉派发者。见 `00-插件功能要求.md` §2 与 `01` §6 第 1 条。

# 验收脚本（17 套）

> 这些是**开发期的验收脚本** —— 一套针对一条链：数据层／信封／状态机／时限／成员卡／目录产出／日志／对外接口／多口接入／轮次口径／派活表态／全流程／系统代收／收口唤醒／打回上限……
>
> **跑法写在各自开头的注释里**（找 `用法：` 或 `跑法：` 那一行），**先读它再跑**。

## ⚠️ 跑之前必须知道的三件事

1. **有 10 套会写运行数据**（`运行\数据\`、`运行\日志\`）—— 它们自己都在头部标了「先备份、跑完恢复」。
   ⇒ **跑之前先备份 `运行\数据\`，跑完恢复**。（`运行\数据\` 在 `.gitignore` 里，不进版本库。）
2. **有 3 套要真环境**：默认后端 `http://127.0.0.1:8787`（可用环境变量 `OFFICE_URL` 改），而且**需要"假人"先在线**。
   假人在 `程序\接入\假人.mjs`（造三个成员 `a`／`b`／`c`），先起后端、再 `node 程序\接入\假人.mjs`。
3. **`M8c-多口接入.ps1` 必须用 PowerShell 跑**，不能用 node —— 它要给子进程喂 stdin、收 stdout。

## 想一口气跑全套？

**没有"一键全跑"**，而且不建议硬凑：这些脚本彼此独立、前提不同（有的要假人、有的要真后端），而且**会互相干扰**（好几套都动同一份运行数据）。

⭐ 建议的顺序：**先跑全隔离的（`M14`／`M15`／`M6`）→ 再跑会写数据的（每组之间备份／恢复 `运行\数据\`）→ 最后跑要真环境的（先起后端 ＋ 假人）**。

## 与别处的关系

- 脚本头部常写「依据：`验收清单-20261003.md` 二·M1」—— 那份清单是**开发期的内部台账**（含过程叙事与历史读数），**没有随包发布**，这里说明一下，免得你去找。
- 协议与本体的说明在 `文档\规范\`；插件的写法在 `插件标准包与插件\`。
- 假人与取卡小工具在 `程序\接入\`（`假人.mjs`／`_取卡.cjs`）—— 它们就是给这些脚本用的。
